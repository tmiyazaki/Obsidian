# 倫理的デザイン (とダークパターン)

## 一行で

> 短期 KPI を上げる UX が、ユーザーの**信頼・自治・幸福**を蝕むことがある。「**できる**」と「**してよい**」は別。

## なぜ重要か

ユーザーの注意・データ・お金を引き出す技術は、過去 20 年で巧妙化しました。「Growth Hacking」と「Manipulation」の境界は曖昧で、デザイナー/エンジニアは**意図せずダークパターンに加担**することがあります。

倫理的デザインは:
- **長期信頼**を育てる(短期 KPI と相反することがある)
- **法的リスク**を減らす(GDPR, FTC, EU DSA, 日本の改正特定商取引法等)
- **チームの自尊心**を支える(「自分の親に見せられるか」)

## ダークパターン分類 (Harry Brignull, EU Deceptive Design Patterns)

### 1. Comparison Prevention (比較妨害)

価格・条件を**比較しづらい**形で提示。
- 機能比較表で他社を不利に
- 計画ごとに別ページで比較不能

### 2. Confirmshaming

却下ボタンに**罪悪感を持たせる**:

```
[ メルマガを購読する ]
[ いいえ、私は割引を受け取りたくありません ]
```

中立的な「いいえ」を「自分にネガティブな何か」にすり替える。

### 3. Disguised Ads

広告を**コンテンツに偽装**。「次の記事」が実は外部広告。

### 4. Fake Scarcity / Urgency

「あと 1 室!」「3 分以内!」が虚偽 or 自動再生のタイマー。

### 5. Forced Action

サービス利用に**不必要な情報・許可**を強制:
- メルマガ購読が必須
- 過剰な権限 (連絡先・位置情報) を要求

### 6. Hard to Cancel ("Roach Motel")

> 入るのは簡単、出るのは難しい

- 解約だけ電話必須
- 登録は 1 ボタン、解約は 5 ステップ
- 「本当に?」を 4 回確認

### 7. Hidden Costs

最終ステップまで**手数料・送料**を隠す。

### 8. Hidden Subscription / Sneak Into Basket

トライアル後の**自動課金**を分かりにくく、または購入時に**追加商品**を勝手に追加。

### 9. Misdirection

注目を**設計者にとって有利な選択肢**に誘導:
- 「同意」ボタンを大きく彩色、「拒否」を地味に
- 既定でチェック済み (オプトイン強制)

### 10. Nagging

定期的に同じ依頼を繰り返す。「通知 ON にしませんか?」を毎回。

### 11. Obstruction

ユーザーの目的達成を**わざと遅らせる**。アカウント削除画面が見つからない。

### 12. Trick Questions

否定形を組み合わせて誤解を誘う:
> 「□ メルマガを受け取らないことに同意しない」

「同意する」がチェックなのか外すのか、読み解けない。

## グッドデザインの倫理原則

### 1. 透明性 (Transparency)

ユーザーが**何が起きるか理解**してから行動する。
- 価格・条件を**最初に**提示
- データの使い道を**読みやすく**
- アルゴリズムの判断根拠を可能な限り説明

### 2. 自治 (Autonomy)

選択を**ユーザー側に保つ**:
- 中立な選択肢の提示 (ボタンの大きさ・色を均等に)
- 「拒否」が同等に簡単
- いつでも変更可能

### 3. 可逆性 (Reversibility)

- 解約は登録と**同等以下**の手数で
- データのエクスポート・削除権
- 重要操作の Undo

### 4. 最小限のデータ

GDPR の「データ最小化」原則:
- 必要なデータだけ収集
- 必要な期間だけ保管
- 必要な範囲だけ共有

### 5. 公平性

アルゴリズムの**偏り (bias)** を意識。
- 訓練データの偏りが結果に出る
- 特定属性 (人種・性別・年齢) で結果が歪まないか
- A/B テスト結果が**特定セグメントに有害**でないか

### 6. ユーザーの利益優先

KPI とユーザー利益が**競合**したとき、長期的にはユーザー利益を選ぶ。
- 滞在時間より満足度
- クリック率より達成率
- 課金より継続価値

## 法規制の概要 (主要)

### GDPR (EU)

- **明示同意**: 既定チェックは無効
- **目的制限**: 同意した目的以外に使えない
- **アクセス権/削除権**: ユーザーが要求できる
- **データポータビリティ**: 別サービスへ持ち出せる
- 違反は**全世界年間売上の 4%** まで

### CCPA / CPRA (カリフォルニア)

- 「個人情報を売らない」オプション必須
- 削除要求対応

### EU DSA / DMA (2024-)

- ダークパターン**明示的禁止**
- 大規模プラットフォーム (VLOPs) の追加義務

### 日本

- 個人情報保護法 (2022 改正): 漏洩通知義務、同意要件
- 特定商取引法 (改正): 定期購入の表示義務、解約方法の明示

## 同意 UI のベストプラクティス

```
✓ クッキー同意は**カテゴリ別**選択可能
✓ 「すべて拒否」「すべて同意」が**同等に目立つ**
✓ 同意撤回が**いつでも可能**
✓ 詳細をクリック可能 (各クッキーの目的・保存期間)
✗ 既定で全部チェック済み
✗ 「同意」だけ目立つ
```

## チームでの実装

### 1. レビューチェックリスト

機能リリース前に:
- [ ] ダークパターン分類のどれかに該当しないか
- [ ] 「拒否」が「承認」と同等の手数か
- [ ] 隠れた契約 (定期課金等) が**明示**されているか
- [ ] データ収集が**最小限**か

### 2. ユーザーリサーチで検出

ユーザビリティテストで「**騙された感**」を観察:
- 「これ、押すと何が起きると思いましたか?」
- 「予想と違いましたか?」

→ [[../30-Interface/User-Research]]

### 3. ポストモーテム

数値が大きく改善した A/B テストは**疑う**:
- 短期だけ改善し、長期 LTV は悪化していないか
- 解約・苦情・カスタマーサポートへの問い合わせが増えていないか

### 4. 内部の「Devil's Advocate」

機能議論に**反対役**を置く ─ 「これ、悪用されるとどうなる?」「弱者を傷つけないか?」

## 説得 (Persuasion) と操作 (Manipulation) の違い

両者は連続体。区別の指針:

| 説得 | 操作 |
|---|---|
| 情報を与えて選ばせる | 情報を歪めて選ばせる |
| 長期利益を強調 | 短期衝動を煽る |
| 撤回可能 | 不可逆 |
| ユーザー利益と整合 | 提供者利益のみ |

「Persuasive Design」と「Dark Pattern」の境界は曖昧だが、**ユーザーの長期幸福**を基準にすると判断しやすい。

## アンチパターン (再掲)

- カウントダウンが**虚偽** or リロードでリセット
- 解約が**電話のみ**
- メルマガ購読**強制チェック**で隠れている
- 「最後のチャンス」が**毎日**届く
- 通知許諾を**起動直後**に強制
- データの利用目的が**法律最低限**しか書かれていない
- 子どもアカウントに**広告ターゲティング**

## チェックリスト

- [ ] 拒否が承認と**同等の手数**か
- [ ] 課金条件・解約方法が**事前に明示**されているか
- [ ] 必要最小限の**データ**だけ収集しているか
- [ ] アクセシビリティ・色の偏りが**人を排除しない**か
- [ ] 通知・許諾要求が**過剰でない**か
- [ ] チーム内に**反対役**が機能しているか
- [ ] 法規制 (GDPR/CCPA/個人情報保護法等) を満たすか
