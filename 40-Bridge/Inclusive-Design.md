# インクルーシブデザイン

## 一行で

> 「**特定の人を除外しない**」アクセシビリティに対し、インクルーシブデザインは「**多様性そのものを設計の入力**にする」アプローチ。

## なぜ重要か

「平均的なユーザー」は実在しません。年齢・能力・言語・文化・状況・経済状態 — あらゆる軸で多様な人々が、それぞれ**異なる文脈**でプロダクトに触れます。多様性を**設計の前提**にすることで:
- 「特殊ケース」が生まれにくい
- 結果的に**全員にとって**良い UX になる
- 法的・倫理的リスクを下げる
- マーケットを広げる

「アクセシビリティ」は出口の検証、「インクルーシブデザイン」は入口の発想。

## アクセシビリティとの関係

```
Universal Design  : すべての人に同一で
Inclusive Design  : 多様な人に多様な解で
Accessibility     : 障害のある人に到達可能に
```

- **アクセシビリティ**: WCAG 等の基準を満たす (出力)
- **インクルーシブデザイン**: 多様な利用者を**設計プロセス**に巻き込む (入力)
- **ユニバーサルデザイン**: 1 つの解で全員に (理想だが理論的)

→ [[../30-Interface/Accessibility]]

## Microsoft Inclusive Design の 3 原則

### 1. Recognize Exclusion (排除を認識する)

- 視覚障害、聴覚障害、運動障害だけが対象ではない
- **状況的・一時的・永続的**な制約すべて

```
腕の損傷 → 永続的・片手
腕の骨折 → 一時的・片手
赤ちゃん抱っこ → 状況的・片手
```

3 つとも**同じ UI 課題**を持つ。永続的障害向けに作った UI は、一時的・状況的にも役立つ。

### 2. Solve for One, Extend to Many

特定の人のために作ると、結果的に**多くの人に**役立つ:

| 元々の対象 | 結果的に恩恵 |
|---|---|
| 視覚障害者向け文字読み上げ | スマートスピーカー全般 |
| 車椅子用スロープ | ベビーカー、台車、キャリーケース |
| ろう者向けキャプション | 騒音環境、無音再生 |
| 手の震え対応の大ボタン | 寒い手、運転中の手袋 |
| 高コントラスト | 直射日光下のスマホ |

### 3. Learn from Diversity

多様な利用者を**設計プロセスに巻き込む**:
- インタビューに多様性
- ユーザビリティテストの被験者多様化
- 多様な視点を持つチーム

→ [[../30-Interface/User-Research]]

## 設計時に考慮する多様性の軸

### 身体的

- 視覚 (盲、弱視、色覚多様性)
- 聴覚 (ろう、難聴)
- 運動 (片手、震え、可動域制限)
- 発話 (構音障害)

### 認知

- 学習障害 (失読症、計算障害)
- 注意・記憶 (ADHD、認知症)
- 自閉スペクトラム

### 言語・文化

- 母語以外でプロダクト利用
- 文化的習慣 (色・絵柄・タブー)
- 暦・通貨・住所形式
- → [[Internationalization]]

### 経済・技術

- 古いデバイス・低速回線
- データ容量制約
- スマホしか持たない (デスクトップなし)

### 状況

- 移動中・通勤
- 騒音 / 静寂
- 直射日光・暗所
- 片手・両手塞がり
- ストレス・疲労

## 設計プラクティス

### 1. ペルソナを多様化

「30 代男性、エンジニア」だけでない:
- 視覚に頼らないユーザー
- 母語が英語でないユーザー
- 古いスマホしか持たないユーザー
- 1 日の終わりに疲れているユーザー

### 2. ストレステスト

- 画面拡大 200%
- スクリーンリーダーのみ
- キーボードのみ
- 低速 3G 回線
- 片手操作
- 認知負荷 (タスクをしながら)

これらを**普通の QA に組み込む**。「a11y チェック」を別フェーズにすると後回しになる。

### 3. 言葉

- 平易な日本語 (中学生でも分かる)
- 専門用語の説明
- スラング・冗談を控える (文化依存)
- 性別・人種・年齢に**中立**な表現

→ [[../30-Interface/UX-Writing]]

### 4. ビジュアル

- 多様な人物表現 (人種・体型・障害・年齢)
- ステレオタイプ (家事 = 女性、エンジニア = 若い男性) を避ける
- 絵文字・アイコンの**文化的中立性**

→ [[../20-Design/Brand-Voice]]

### 5. デフォルト

「**マイノリティをデフォルトに**」する設計判断:
- 通知デフォルト OFF (押し付けがましくない)
- 字幕デフォルト ON (字幕が必要な人 + 騒音環境)
- ダークモード自動 (光感受性配慮)

## 言語のインクルーシブ性

### 性別中立

```
❌ "Welcome, Sir/Madam"
✅ "Welcome"

❌ "Each user must enter his password"
✅ "Each user must enter their password"
```

### 能力中立

```
❌ "Click here to..."  (クリックできない人がいる)
✅ "Select to..." / "Choose..."
```

### 年齢中立

```
❌ "Designed for digital natives"
✅ "Easy for everyone"
```

## チームの多様性

> "If you're designing for everyone, you need everyone in the room."

- 雇用・登用の多様性
- 外部レビュー (障害当事者・他文化圏)
- 多様な視点を**安全に出せる**文化 (心理的安全性)

→ [[Critique-Culture]]

## アクセシビリティ標準との接続

→ [[../30-Interface/Accessibility]]

WCAG 2.2 / EN 301 549 / JIS X 8341-3 等の**法的・規格的要件**を満たすことは最低ライン。
インクルーシブデザインはその**上流**で、「そもそも設計でどう取り込むか」を考える。

## インクルーシブな採用と協働

- リモートワーク (場所の制約)
- 非同期コミュニケーション (時間帯)
- 字幕付き会議
- 議事録の共有 (聴覚障害者)
- ドキュメント文化 (口頭依存しない)

→ [[Documentation-as-Product]]

## エシカルなトレードオフ

100% インクルーシブは現実的でない。意識的にトレードオフを記録:

```
制約: ベース価格を抑えるためモバイル中心。
影響: PC のみのユーザーは利用が限定。
緩和策: 主要機能はレスポンシブで PC でも動作。
```

「気づいているが今は対応しない」と「気づいていない」は**雲泥の差**。

## アンチパターン

- 「ターゲットユーザー」を絞りすぎて**対象外**を設計から排除
- a11y を**最後の QA フェーズ**に押し付ける
- ステレオタイプ的なペルソナのみで設計
- 多様性をマーケティングメッセージにだけ使い、設計は変えない (Diversity-washing)
- 「**全員のため**」と言いながら結局誰の声も聞かない
- 法的要件を満たすだけで**形骸化**

## チェックリスト

- [ ] 多様な**利用文脈**を想定したか (永続・一時・状況)
- [ ] 設計プロセスに**多様な人**が関与しているか
- [ ] 言葉・ビジュアルに**ステレオタイプ**がないか
- [ ] **デフォルト**がマイノリティに優しいか
- [ ] 古いデバイス / 低速回線でも**動く**か
- [ ] アクセシビリティ標準 (WCAG AA) を満たすか
- [ ] 意識的なトレードオフが**記録**されているか
