# 名前付けという設計

## 一行で

> 名前は「**コード**でも**UI**でも**情報構造**でも、最も読まれるドキュメント**」。命名は領域を貫く設計行為。

## なぜ重要か

- コードでは: 半年後の自分と他人がそのコードを使い続けるための鍵 → [[../10-Coding/Naming]]
- UI では: ユーザーがメニューを辿るときの**現在地と目的地の橋**
- IA では: コンテンツが**探さずに見つかる**ための地図

3 領域は**別々の名前**ではなく、**ユビキタス言語**として一致しているのが理想です。

## 三領域の命名が一致するとは

例: e コマースの「決済」機能。

| 場所 | あるべき呼び方 |
|---|---|
| ユーザー向け文言 | 「お支払い」 |
| メニューラベル (IA) | 「お支払い」 |
| ドメインモデル (コード) | `Payment` |
| API エンドポイント | `/payments` |
| デザインシステムの component | `PaymentForm` |
| Figma Frame | `Payment / Confirm` |

ここで「`Transaction`」「`Checkout`」「`Order`」が混在し始めたら危険信号。

## 一貫させる方法

### 1. ユビキタス言語(DDD 由来)

ドメイン駆動設計の中心概念。**業務側**と**開発側**が**同じ語彙**で話す。

> 「この機能、`Transaction` と呼びますね」 → 業務側「業務では『決済』と言います」 → コードでも `Payment` に統一

これを**ドキュメントに残し**、新メンバーに継承する。

### 2. 用語集 (Glossary)

リポジトリ直下の `GLOSSARY.md` に:

```
Order: 注文。お客様が商品を購入する申し込み。
  関連: OrderLine, Customer, Payment

Payment: 決済。注文に対する支払い処理。
  関連: Order, RefundRequest

Refund: 返金。Payment の取り消し処理。
```

仕様書、Figma、コード、メニューラベルがこの用語集を**唯一の真実**とする。

### 3. リネームを恐れない

業務理解が深まると、初期命名が古びる。**気づいたタイミングでリネーム**する文化を持つ。

- IDE の rename 機能で機械的に
- マイグレーションスクリプトで DB 列も同期
- Figma の Component もリネーム
- ドキュメントの grep & replace

「いつかリネームしよう」は永遠に来ない。

## 領域別の命名のコツ(再掲・整理)

### コード命名 → [[../10-Coding/Naming]]

- 動詞 vs 名詞、単位の埋め込み、真偽値は質問形

### UI 命名

- ユーザーの**業務語彙**で書く
- 専門用語を避ける(`Authentication` ではなく「ログイン」)
- 同じものを 2 箇所で別の名前で呼ばない(「設定」と「環境設定」を共存させない)
- 略語は文化依存:`PR` は知らない人もいる

### IA 命名 → [[../30-Interface/Information-Architecture]]

- カテゴリは**並列の同じ抽象度**(「商品」「ブログ」「支援する」 ← 抽象度バラバラ)
- 動詞リスト/名詞リストで**揃える**
- カードソートでユーザーが自然に作るカテゴリ名を採用

## アンチパターン: 命名の崩壊

### 1. 二重化

```
ドメイン: User
コード: User, Member, Account, Person ← 全部同じ?違う?
```

→ 用語集で**意味の境界**を明示。

### 2. メタファ衝突

```
チケット (タスク管理)
バッジ (ピン)
ステッカー (装飾)
```

メタファが多すぎると**抽象が混線**。1 メインメタファに揃える。

### 3. 国際化崩壊

```
英語: "Setting"
日本語: 「設定」「環境設定」「セッティング」← 翻訳がバラバラ
```

→ i18n ファイルで一元管理。翻訳ガイドラインを持つ。

### 4. 内部用語の漏れ

エンジニアの呼び方 (`User Service`, `Auth Layer`) が**ユーザー向け文言**に混入する。

## リネームのタイミング

- 業務理解が変わったとき(早めに)
- 新人が「これ何?」と詰まる用語(継承の摩擦が大)
- 矛盾が露呈したとき(混在を放置すると拡散する)
