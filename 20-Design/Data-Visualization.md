# データビジュアライゼーション

## 一行で

> グラフは「**装飾された数値**」ではなく、「**比較・関係・分布を視覚に変換**して**意思決定**を支える道具」。

## なぜ重要か

数値表は正確だが、**パターン**が見えない。良いグラフは数秒でトレンド・外れ値・関係を伝えます。逆に、悪いグラフは**嘘を言わずに誤読を誘う**(切られた y 軸、誇張された 3D)。

## 5 つの問いから始める

グラフを作る前に:

1. **誰が見るか** (経営層、開発者、エンドユーザー)
2. **何を伝えたいか** (1 つに絞る)
3. **どの関係か** (比較・推移・分布・構成・関連)
4. **読み手は何を決めたいか**
5. **どこで見るか** (ダッシュボード、レポート、UI 内)

「綺麗なグラフ」より「**疑問に答えるグラフ**」。

## 関係 → グラフの選択

| 関係 | 推奨 | 注意 |
|---|---|---|
| 推移 (時系列) | 折れ線 | 多すぎる線は読めない (5 系列まで) |
| 比較 (カテゴリ) | 横棒・縦棒 | 0 から始める |
| 構成 (割合) | スタック棒、ツリーマップ | 円グラフは 5 要素まで |
| 分布 | ヒストグラム、箱ひげ | 平均だけは罠 |
| 関連 | 散布図 | 相関 ≠ 因果 |
| 順位 | 横棒(降順) | 値ラベルを併記 |
| 地理 | コロプレス、点 | 面積バイアスに注意 |

円グラフは**3〜4 要素**まで。それ以上は**横棒**に切り替える(目で角度を比較するのは難しい)。

## 知覚の優先順位 (Cleveland & McGill)

人間が**正確に比較できる**順:

```
1. 共通軸上の位置  ← 最高 (横棒・縦棒)
2. 異なる軸上の位置
3. 長さ
4. 角度・傾き
5. 面積
6. 体積
7. 色相 / 彩度          ← 最低 (誤差大)
```

「**色だけで量を表す**」のは最弱の方式。マップの色塗り (choropleth) も補助情報を必ず付ける。

## 設計原則

### 1. データインク比 (Tufte)

> "Above all else show the data."

装飾を削り、**データが語るインク比**を最大化:
- 不要な枠線・背景・3D を削除
- グリッドは薄く
- 凡例は系列の**直接ラベル**化が読みやすい

### 2. ゼロベースライン (棒グラフ)

棒グラフの y 軸は**必ず 0 から**。途中から始めると差が誇張される (グラフィカルライ)。
折れ線は文脈に応じて切り捨て可。

### 3. ソート

カテゴリの並びに意味が無いなら**値順**に並べる。アルファベット順は読み手の仕事を増やす。

### 4. 軸ラベルと単位

- 単位を明示: `売上 (千円)`
- スケールが変わるなら $ → ¥ → 桁を統一
- 対数スケールには明示マーク

### 5. 注釈で物語を加える

外れ値・転換点に**注釈**を入れる:

```
2024-12-25 ┃ ←── キャンペーン開始
           ↓
       ──────●──────────
```

「読者が気づくべきこと」を**先回り**して指す。

## 色の使い方

→ [[Color-Theory]]

### カテゴリカル

5〜8 色までの**識別**用。色相を均等に。色覚多様性配慮 (Okabe-Ito, viridis ベース)。

### 順序付き (Sequential)

低 → 高 を**1 色相の明度勾配**で:
```
viridis, blues, oranges
```

### 発散 (Diverging)

中央 (基準) からプラス/マイナスへ:
```
red ← white → blue
```

ヒートマップで **「平均からの差**」を見せる時に最適。

### 強調

「**1 つだけ目立たせる**」場合、他をグレーに、注目を**1 色だけ**着色。

## ダッシュボードの構成

### 階層

```
レベル 1: 主要 KPI (大きく、上)
レベル 2: ドリルダウン (中サイズ、左→右に詳細化)
レベル 3: 生データ・テーブル (下)
```

### F パターン

→ [[Visual-Hierarchy]]

主要数値は**左上**、関連グラフを右へ展開。下方向に補足。

### 5 秒ルール

5 秒見て**主要メッセージ**が分かるか。詰め込みすぎたら分割。

## インタラクション

- **ホバー詳細** (tooltip): 個別値の精確な確認
- **フィルタ・ファセット**: 期間、セグメント
- **ズーム/パン** (時系列): 詳細期間の調査
- **ドリルダウン**: 集約 → 個別

ただし、**静止画でも理解できる**ことが基本。インタラクション必須は壊れやすい。

## アクセシビリティ

- 色だけで意味を伝えない (パターン、形、ラベル併用)
- 凡例は近くに、または直接ラベル
- データ表を**代替表現**として提供 (`<table>`)
- スクリーンリーダー向け要約 (`aria-label`, `<desc>`)
- 色覚シミュレーションでチェック

## 嘘をつくグラフ (避ける)

- y 軸を **0 から始めない** (差が誇張)
- **デュアル Y 軸** (相関を捏造)
- **3D 効果** (奥行きで小さく見える)
- **不揃いな間隔** の x 軸
- **チェリーピック**された期間
- 体積で表現 (面積で十分)

倫理的な表現は信頼の基盤。→ [[../40-Bridge/Ethical-Design]]

## ダッシュボードの空・エラー・読込

→ [[../30-Interface/Loading-States]]

- 空: 「データがまだありません」+ 取得手順
- 読込: スケルトン (グラフの形を予約)
- エラー: 何が起きたか + 再試行
- 部分データ: 「直近 7 日分のみ」明示

## ライブラリ

| ライブラリ | 強み |
|---|---|
| **Recharts** / **Visx** (React) | コンポーネント志向 |
| **Chart.js** | 学習低、汎用 |
| **D3.js** | 完全自由、学習高 |
| **Vega-Lite** | 宣言的、表現豊富 |
| **ECharts** | 大規模・高性能 |
| **Observable Plot** | 文芸的、データ探索 |

ダッシュボード用の**プロダクション**には Recharts/Visx/ECharts、**プロトタイプ**には Vega-Lite/Plot。

## アンチパターン

- すべてのグラフを**3D 円グラフ**で
- 系列が 10 本以上の折れ線(読めない)
- 軸ラベル無し
- データ密度が低い**スカスカ**ダッシュボード
- 2D の値を**面積**で誤って二乗
- ビジュアルが派手で**主要数値が埋もれる**
