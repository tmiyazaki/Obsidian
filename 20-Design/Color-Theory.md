# カラーセオリー

## 一行で

> 色は「**装飾**」ではなく「**意味と感情と階層**」を運ぶデータチャンネル。

## なぜ重要か

色は最も瞬時に伝わる視覚情報です。ブランドを記憶させ、アクションを誘導し、エラーを警告し、グルーピングを示します。同時に、色覚多様性・コントラスト不足・文化差により**最も誤解されやすい**チャンネルでもあります。

## 中核モデル

### HSL / HSB(人間に直感的)

- **H (Hue)**: 色相 (0–360°)
- **S (Saturation)**: 彩度 (0–100%)
- **L (Lightness) / B (Brightness)**: 明度

UI 設計では HSL の操作が直感的。**明度だけ**を調整して階段を作ると一貫した「色のスケール」が得られる。

### LCH / OKLCH(知覚均等)

`#FF0000` と `#00FF00` は HSL では明度が同じ (50%) でも、**目には別の明るさ**に見える。OKLCH は知覚に近いため、トークン設計では今最も推奨される(CSS Color Level 4 で利用可)。

```css
:root {
  --primary-50:  oklch(97% 0.02 250);
  --primary-500: oklch(60% 0.18 250);
  --primary-900: oklch(20% 0.10 250);
}
```

### RGB / HEX(機械の言葉)

実装で頻出。デザインでは HSL/OKLCH で考え、出力時に HEX に変換する流れが扱いやすい。

## カラースケールの作り方

### ステップ階段(50, 100, …, 900)

ブランドカラーを起点に、**明度**を均等に変化させる 9〜10 段階を作る。Material / Tailwind / Radix が採用する方式。

```
50:  ほぼ白い、背景・薄いハイライト
100: 帯・微妙な強調
500: ベース(ボタン、リンクの主要色)
700: ホバー・強アクセント
900: 文字、最濃の強調
```

### Tints / Shades / Tones

- Tint: 白を混ぜる
- Shade: 黒を混ぜる
- Tone: グレーを混ぜる

### 隣接色のトラップ

明度を機械的に等差にすると、HSL では**緑系が浮く・青系が沈む**現象が出る。**目で確認しながら**、または OKLCH を使って解決。

## 色の役割を定義する(セマンティック)

色そのもの (`blue-500`) と、**役割** (`color-primary`) を分ける:

```
ブランド色:  brand-primary, brand-secondary
機能色:     color-success, color-warning, color-danger, color-info
グレー軸:   neutral-50 〜 neutral-900
表面:       surface-base, surface-raised, surface-overlay
テキスト:   text-primary, text-secondary, text-disabled
ボーダー:   border-default, border-strong
```

セマンティック層を介することで、**ダークモードで brand を変えずに background を反転**できる(→ [[Design-Tokens]])。

## 配色

### 60-30-10 ルール

画面の色配分を **ベース 60% + 補助 30% + アクセント 10%** に。アクセントは「行動を促す場所」だけに使う。

### スキーム

- **モノクロマティック**: 同じ色相で明度違い。落ち着き、情報密度高め
- **アナログ**: 色相環で隣接(青〜緑)。穏やか
- **コンプリメンタリ**: 補色(青⇔オレンジ)。強コントラスト
- **トライアド**: 等間隔 3 色。活発
- **スプリットコンプリメンタリ**: 補色を 2 色に分ける。強さを残しつつ角を削る

UI では**モノクロマティック + アクセント 1 色**が破綻しにくい。

## 文化と意味

色の象徴は文化依存:
- **赤**: 西洋では危険、東アジアでは祝祭
- **白**: 西洋では純潔、東アジアでは喪
- **緑**: 西洋では成功・許可、中東では宗教的・神聖

国際向けの製品では「赤は警告、緑は OK」を**色だけに依存しない**(色覚配慮も同じ)。

## アクセシビリティ

### コントラスト

WCAG:

| 用途 | AA | AAA |
|---|---|---|
| 通常テキスト | 4.5 : 1 | 7 : 1 |
| 大型テキスト (18pt+) | 3 : 1 | 4.5 : 1 |
| UI コンポーネント / グラフィック | 3 : 1 | — |

### 色覚多様性

- **色だけで意味を伝えない** — アイコン、テキスト、形を併用
- 赤緑の区別が困難なケースが多い
- ツール: Stark, Sim Daltonism, Chrome DevTools のエミュレーション

→ [[../30-Interface/Accessibility]]

## ダークモード設計

- 単純に色を反転しない
- **ピュアブラック (#000)** は OLED で深いがコントラストが強すぎる。`#0F1115` 程度のオフブラックが目に優しい
- **彩度を下げる**: 暗い背景で同じ彩度は刺さりすぎる
- **影は逆向きには使わない**: 暗い面で影は見えにくい → 代わりに**明度の差**で奥行きを示す

## アンチパターン

- ブランドカラーをアクション・エラー両方に使い**警告と承認の区別が崩壊**
- 5 色以上のアクセントが**競合**して意味が分からない
- 色だけで状態を示し、**色覚多様性ユーザーに不可視**
- ダークモードで真っ黒背景と高彩度の組み合わせでチカチカする

## チェックリスト

- [ ] **役割名**(primary, danger 等)で色を扱っているか
- [ ] アクセントは画面の **10% 以内**か
- [ ] テキスト/背景の**コントラスト比**が AA 以上か
- [ ] 色だけで意味を伝えていないか
- [ ] ダークモードでも整合するか
