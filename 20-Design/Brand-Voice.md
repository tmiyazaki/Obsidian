# ブランドアイデンティティとビジュアルボイス

## 一行で

> ブランドは「**ロゴ**」ではなく「**プロダクトの全感覚チャネルから一貫して感じられる人格**」。視覚・言葉・モーション・音が**同じ声**で語る状態を作る。

## なぜ重要か

機能で差別化が難しい時代、ブランドは**選ばれ続ける理由**になります。良いブランドは:
- **記憶される** (再認・想起)
- **信頼される** (一貫性 = プロらしさ)
- **共感を呼ぶ** (価値観への共鳴)

ブランドは飾りではなく、**意思決定のフィルタ**。「我々は X だ」と言えれば、無数の些末な決定が早くなる。

## ブランドの構成要素

```
┌────────────────────────────────────────┐
│  ブランドミッション・価値観・ストーリー  │  ← 不変層
├────────────────────────────────────────┤
│  パーソナリティ (人格・声色)              │
├────────────────────────────────────────┤
│  ビジュアル: ロゴ・色・タイポ・モーション   │  ← 可変層
│  ボイス & トーン                         │
│  写真・イラスト方向性                     │
└────────────────────────────────────────┘
```

下層 (ビジュアル) はリブランドで変わるが、上層 (人格) は基本不変。

## パーソナリティ (Brand Personality)

ブランドを**人**に例えると誰か:
- **真面目な専門家** (BMW, IBM, Bloomberg)
- **革新者** (Apple, Tesla)
- **親しみやすい仲間** (Slack, Notion)
- **遊び心ある挑戦者** (Mailchimp, Duolingo)
- **静かで美しい職人** (Muji, Aesop)

「**5 つの形容詞**」で定義する: たとえば「Confident, Warm, Pragmatic, Modern, Inclusive」

「我々が**そうである**」と「我々は**そうではない**」を両方明記すると判断基準が立つ:

```
We are:           We are not:
- Confident       - Arrogant
- Warm            - Sentimental
- Pragmatic       - Boring
- Modern          - Trendy
- Inclusive       - Pandering
```

## ロゴ

### 6 種の典型

1. **Wordmark** (Google, Coca-Cola): 文字だけ
2. **Lettermark** (IBM, HBO): 頭文字
3. **Pictorial** (Apple, Twitter bird): 絵
4. **Abstract** (Nike swoosh, Airbnb): 抽象記号
5. **Mascot** (Michelin, KFC Colonel): キャラクタ
6. **Combination** (Adidas, Slack): 文字 + 記号

### 良いロゴの性質

- **Simple**: 5 秒で描ける
- **Memorable**: 一度見たら覚える
- **Versatile**: 5cm でも 5m でも、白黒でも、ICO でも機能
- **Appropriate**: ブランド人格と一致
- **Timeless**: 5 年で古びない

### スケールバリエーション

```
Full lockup → Compact → Symbol only → Favicon (16x16)
```

サイズに応じて**簡略化したバージョン**を用意。1 つのロゴをすべての場所に詰め込まない。

### Clearspace と最小サイズ

ロゴ周りに**最小余白**を定義 (`= ロゴの一部のサイズ`)。最小印刷サイズも明示 (例: 16px / 8mm)。

## カラーシステム

→ [[Color-Theory]]

ブランド固有の追加要素:
- **プライマリブランドカラー**: 1〜2 色
- **セカンダリ**: アクセント、季節展開
- **モノクロ**: グレースケールでもブランドが伝わるか

## タイポグラフィ

→ [[Typography]]

ブランド観点:
- **ディスプレイ用**: ロゴ・ヒーロー (個性強い、読みづらくてよい)
- **本文用**: UI、長文 (読みやすさ最優先)
- **2 ファミリー以内**で完結
- 商用ライセンスを確認 (アイコンフォント・SaaS で使えないものあり)

「**カスタムフォント**」は強い差別化だがコストも大。デザインシステムの自由度が出る規模になってから検討。

## ビジュアルボキャブラリ

ブランド固有の**形・パターン・質感**を定義:
- **形状言語**: 角丸 vs 直角、有機的 vs 幾何的
- **イラスト**: スタイル (フラット / 線画 / 質感あり)、人物表現 (写実 / 抽象 / 多様性)
- **写真**: 撮影角度・色温度・人物の距離感
- **アイコン**: → [[Iconography]]
- **モーション**: → [[Motion-System]]
- **テクスチャ・グラデーション・パターン**

これら全てが「**同じプロダクト**」と感じさせる。

## ボイス & トーン

→ [[../30-Interface/UX-Writing]]

- **ボイス**: 不変の人格
- **トーン**: 状況で変わる温度

ブランドガイドに「**してよい**」と「**してはいけない**」両方を例で示す:

```
✓ 「あなたの選んだ写真がギャラリーに追加されました」
✗ 「ファイルアップロードが完了しました (success: true)」
✗ 「やったね!最高の写真がギャラリーへ!」 (過剰)
```

## ブランドガイドラインの構成

```
1. ブランドストーリー / ミッション
2. パーソナリティ (5 形容詞 + 反例)
3. ロゴ (使用法・禁止例・最小サイズ)
4. カラー (役割・組み合わせ)
5. タイポグラフィ
6. アイコン・イラスト・写真
7. モーション (時間・イージング・意味)
8. ボイス & トーン (例文集)
9. アプリケーション (名刺・SNS・広告・UI)
10. 申請窓口 (新規アセットの相談先)
```

公開例: Mailchimp, Atlassian, Spotify, Polaris (Shopify), Material You。

## ブランドとデザインシステムの関係

```
ブランド = なぜ・誰・何を語るか (戦略レイヤ)
    ↓ 翻訳
デザインシステム = どう見せ、どう作るか (実装レイヤ)
```

ブランドはデザインシステムの**上流**。リブランド時、デザインシステムは**書き換える**ことになるため、両者の関係を明示しておく。

→ [[Design-Systems]]

## リブランドの判断

### 必要なとき

- 事業ピボット (対象顧客が変わる)
- 競合と区別がつかなくなった
- ブランドが**負の連想**を持ってしまった
- 老朽化で**プロダクトと矛盾**

### 不要なとき

- 単に「飽きた」
- リーダー個人の好み
- 売上低下を**ブランドのせい**にしている

リブランドはコストが高い (印刷物・ドメイン・Google ランクへの影響)。理由が薄ければ**リフレッシュ**(アップデート)で十分。

## ブランド一貫性のガバナンス

- **DAM** (Digital Asset Management): ロゴ・写真・テンプレートを一元管理
- **テンプレート**配布: スライド・名刺・SNS バナー
- **承認フロー**: 新規アセット制作の窓口
- **教育**: 全社員にブランドストーリーを共有 (営業・サポートも声の一部)

## アンチパターン

- ロゴだけがブランドだと思っている
- 5 色のメインカラー (どれが主か分からない)
- ガイドが**ロゴルールだけ**で言葉・モーションが空白
- 流行のスタイル (グラデーション、ニューモーフィズム) を**理由なく**追従
- アクセシビリティ無視のブランドカラー
- ガイドが**綺麗な PDF** で終わり、現場で参照されない
- 部署ごとに**勝手なテンプレート**

## チェックリスト

- [ ] パーソナリティが**5 形容詞 + 反例**で定義されているか
- [ ] ロゴが**白黒・極小**でも機能するか
- [ ] カラーが**ブランド・機能・グレー軸**で整理されているか
- [ ] ボイス & トーンに**例文**があるか
- [ ] 主要アセットが**1 か所**から取得できるか
- [ ] アクセシビリティ要件と**矛盾していない**か
- [ ] ブランドガイドが**実装可能な形**で書かれているか
