# アイコノグラフィ

## 一行で

> アイコンは「**言葉のいらない言葉**」。ただし**学習され、文化に依存し、文脈で意味が変わる**。

## なぜ重要か

アイコンは画面密度を下げ、視線を素早く目的へ運びます。一方で「**直感的**」と思われがちなアイコンの多くは**学習に依存**しており、初見では意味が伝わりません(ハンバーガーメニュー、フロッピーディスク=保存、など)。

## 設計原則

### 1. 視覚的一貫性

セット全体が**同じ言語**で描かれていること:
- **ストローク幅**(細線 1.5px / 太線 2px など、混在させない)
- **コーナー半径**(全アイコン同じ)
- **ターミナル**(線の終端: 角・丸・斜め)
- **キーラインシェイプ**(サークル、スクエア、…で統一されたボリューム感)
- **グリッド**(24x24 / 16x16 などサイズグリッドにスナップ)

混在させるとセット感が崩れる:

```
✗ 線の細さがアイコンによって違う
✓ 全アイコンが 1.5px ストロークで統一
```

### 2. ピクセル整合 (Pixel Snapping)

小サイズで**ぼやけ**を防ぐため、整数ピクセルにスナップ。Figma の Pixel Preview で確認。

### 3. 光学補正

数学的な中央が**目にとっての中央**ではない。三角形・斜めの形は**光学的に**ずらして調整。例:再生ボタンの三角形は、ボタン中央に対して数 px 右にずらすほうが「中央に見える」。

### 4. 意味の慣習を壊さない

| アイコン | 期待される意味 |
|---|---|
| ハンバーガー (☰) | メニュー / ナビ |
| 虫眼鏡 | 検索 |
| ベル | 通知 |
| 歯車 | 設定 |
| ハート | お気に入り / いいね |
| 共有(枝分かれ) | シェア |

慣習を逆手に取ると**ユーザーが間違える**。新規アイコンを発明するときは、**既存パターンに乗れないか**を先に考える。

## ラベルとの組み合わせ

- **アイコンのみ**: スペース節約、慣れたユーザー向き
- **アイコン+ラベル**: 学習コストが下がる、AAA アクセシビリティ
- **ラベルのみ**: アイコンが文化的に通じないとき

研究: **アイコン+ラベル** が最もタスク完了が早い。アイコンだけは「思い出さないと押せない」状態を生む。

## アクセシビリティ

### 1. ラベルを必ず提供

スクリーンリーダー向けに `aria-label` または `<title>`:

```html
<button aria-label="メニューを開く">
  <svg ...><!-- ハンバーガー --></svg>
</button>
```

### 2. タップ領域

アイコンサイズ ≠ タップ領域。**最小 44x44px (iOS) / 48x48dp (Android)**。
ボタン・パディングで領域を確保する。

### 3. コントラスト

線アイコンは塗りアイコンより視認性が低い。背景に対するコントラストを 3:1 以上に。

## 実装の選択肢

### SVG スプライト

```html
<svg><use href="#icon-search" /></svg>
```

長所: HTTP リクエスト 1 回、CSS で色制御。
短所: ビルド設定が必要。

### インライン SVG

各場所に SVG を直書き or コンポーネント化(`<Icon name="search" />`)。
長所: 動的色変更、tree-shaking。
短所: 重複コード。

### アイコンフォント

絵文字のように扱える。長所: 古い手法でサポート広い。短所: アクセシビリティ・色制御で制限あり。**新規採用は非推奨**。

### Lucide / Tabler / Heroicons / Phosphor

オープンソースの**完成したアイコンセット**。一貫性が保証されており、自前で作るより質が高いケースが多い。**ブランド固有アイコンだけ自作**する方針が現実解。

## アンチパターン

- セット内で**ストローク幅・角の取り方が不揃い**
- 慣習に反する意味割り(歯車を「お気に入り」に使う等)
- アイコンだけでアクションを示し、**ラベル無し**
- 16px 以下で**詳細が潰れる**
- 色だけで**状態を区別**(色覚多様性に配慮なし)

## チェックリスト

- [ ] セット全体で**ビジュアル言語**が統一されているか
- [ ] **慣習**を尊重しているか(発明していないか)
- [ ] **ラベル**または `aria-label` があるか
- [ ] **タップ領域**が 44px 以上確保されているか
- [ ] 主要サイズ (16/20/24px) で**潰れない**か
