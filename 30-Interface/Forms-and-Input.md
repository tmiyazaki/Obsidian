# フォームと入力

## 一行で

> フォームは「**ユーザーがシステムに与える唯一の構造化された声**」。一文字でも不要に書かせない、**省力化**が美徳。

## なぜ重要か

フォームは離脱の温床。フィールド一つ増えるごとにコンバージョン率は下がります。逆に、よく設計されたフォームは:
- **誤入力**を起きさせない
- 起きてしまっても**素早く正す**手段を提供
- ユーザーの**労力を最小化**する

## 設計原則

### 1. 必要最小限の項目

**「あるとよい」フィールドはほぼ不要**。後で取得できる情報は後で。

- アカウント作成: メール + パスワード(名前すら任意で)
- チェックアウト: ゲスト購入を最優先

### 2. 一列レイアウト(原則)

複数列より単一列のほうが視線移動が少なく、完了率が高い(研究多数)。

```
[ Name           ]
[ Email          ]
[ Password       ]
```

例外: 関係の強い短いフィールド(姓 + 名、市 + 郵便番号)。

### 3. ラベルは上、見える位置に

- ラベル左配置: スマホ で破綻、視線移動増
- プレースホルダのみ: 入力中に消える → 思い出せない
- **上配置が標準**:

```html
<label for="email">メールアドレス</label>
<input id="email" type="email" />
```

### 4. 適切な input type

```html
<input type="email" />     <!-- @ 付きキーボード -->
<input type="tel" />       <!-- 数字キーパッド -->
<input type="number" />    <!-- 数値、増減ボタン -->
<input type="date" />      <!-- ネイティブ日付ピッカー -->
<input type="search" />    <!-- 検索アイコン、× ボタン -->
<input type="url" />       <!-- URL 用キーボード -->
```

モバイルキーボードが切り替わり、ユーザーの手間が減る。

### 5. autocomplete を適切に

```html
<input autocomplete="given-name"  name="firstName" />
<input autocomplete="family-name" name="lastName" />
<input autocomplete="email"       name="email" />
<input autocomplete="postal-code" name="zip" />
<input autocomplete="cc-number"   name="cardNumber" />
<input autocomplete="new-password" name="password" />
```

ブラウザ・パスワードマネージャの**自動入力**に乗れる。離脱を確実に減らす最大の小技。

### 6. バリデーションのタイミング

| タイミング | 適すケース |
|---|---|
| 入力中 (`input`) | パスワード強度、利用可能名チェック、文字数制限 |
| フォーカスを離れた時 (`blur`) | フォーマット検証(メール形式・電話番号) |
| 送信時 (`submit`) | 全フィールドの最終チェック |

「入力中に都度赤くする」のは**不快**。**ユーザーが書き終えたサイン (blur)** で評価する。

### 7. エラーメッセージ

3 要素を含める:
1. **何が問題か**
2. **なぜ問題か**(任意)
3. **どう直すか**

```
❌ 「不正な値です」
✅ 「メール形式で入力してください(例: name@example.com)」
```

エラーは**該当フィールドの近く**に出す。サマリで上にまとめるのは追加策。

### 8. パスワードフィールド

- **可視化トグル**(目アイコン)を提供
- 強度メーター
- 推奨ルールは**事前に表示**(送信失敗で初めて知るのは×)
- `autocomplete="new-password"` でパスワードマネージャに保存させる
- 再入力フィールドより**可視化**で代替するほうが摩擦少

### 9. プライマリアクション

- **ボタンは 1 つ**(キャンセルはリンクや薄いボタンで二級扱い)
- **動詞 + 目的語**: 「送信」より「アカウントを作成する」
- 押下後は**ローディング状態**を示し、二重送信を防ぐ

## 長いフォームの分割

**分割の方法**で離脱率は大きく変わる。

### ステップ式 (Wizard)

```
[ 基本情報 ] → [ 配送先 ] → [ お支払い ] → [ 確認 ]
```

- 進捗インジケータを上部に
- 戻れる、データは保持
- 各ステップで**所要時間**を示すと完了率が上がる

### アコーディオン

各セクションを畳み、現在のセクションだけ展開。
- 進捗を見ながら入力できる
- 戻りやすい

### 動的開示

選択肢に応じて項目を増減:

```
□ 法人として登録する
  → 会社名、登録番号、… が出現
```

不要なフィールドを**最初から見せない**。

## モバイル特有の配慮

- 数値・電話・メールには適切な input type
- ラベルとフィールドのギャップを十分に
- 送信ボタンはサムゾーンに(下端の親指届く範囲)
- キーボードに被らないよう **scroll-into-view**

```css
input:focus { scroll-margin-top: 80px; }
```

## アクセシビリティ

- `<label for>` で必ず紐付け
- `aria-invalid="true"` + `aria-describedby` でエラー説明
- 必須項目の表示は**色だけでなく**`aria-required` と `*` 印を併用
- フォーカス順序が**視覚順序と一致**

```html
<label for="email">メールアドレス *</label>
<input id="email" type="email" required
       aria-describedby="email-error" aria-invalid="true" />
<p id="email-error" role="alert">メール形式で入力してください</p>
```

## アンチパターン

- 必須項目を**すべて**マークする(色だけ・`*` だけ・無し のいずれか統一)
- パスワード制約を**送信失敗で初めて知る**
- バリデーション失敗で**入力した値が消える**
- CAPTCHA だらけ
- フィールドが多くて**最初に圧倒**される
- 「キャンセル」が「送信」と同じ強度

## チェックリスト

- [ ] フィールド数を**最小限**に削ったか
- [ ] **autocomplete** 属性を適切に付けたか
- [ ] input type が**目的に合致**しているか
- [ ] エラーは**何を・どう直すか**を伝えているか
- [ ] **キーボードのみ**で完結するか
- [ ] スマホで**実機**確認したか
- [ ] 二重送信を**防止**しているか
