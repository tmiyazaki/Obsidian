# 認知アクセシビリティ

## 一行で

> WCAG 2.x は**視覚・聴覚・身体**に注力するが、**認知**(ADHD、失読症、自閉、認知症、ストレス、疲労)は手薄。「集中・記憶・理解」を**設計対象**にする。

## なぜ重要か

人口の**5-10%** が学習障害、**5%** が ADHD、**1-2%** が自閉スペクトラム。
加えて**全員が時として**:
- 疲労 → 集中力低下
- ストレス → 理解力低下
- マルチタスク → 認知過負荷

認知配慮の UI は**全員に**役立つ ─「**Solve for one, extend to many**」 → [[../40-Bridge/Inclusive-Design]]

WCAG 2.2 / 3.0 で認知ガイドライン拡充中。

## 認知の多様性

### 失読症 (Dyslexia)

文字の認識・処理の困難:
- 文字が**動く・歪む**ように見える
- 行の追従が困難
- 略語・専門用語が苦手

設計:
- フォント: **OpenDyslexic** や **Atkinson Hyperlegible**
- 短い行長 (45-65 字)
- 十分な行間 (1.5+)
- 大きめのフォント (16px+)
- **左揃え**(両端揃えは行間が伸縮して読みにくい)
- 略語は**展開を併記**

→ [[../20-Design/Typography]]

### ADHD

注意の維持・切替・抑制の困難:
- 集中持続が短い
- 衝動的判断
- 同時複数情報で混乱

設計:
- **タスクを小さく**分割
- 進捗を**頻繁に**表示
- アニメ / 動画自動再生**なし**(集中阻害)
- 重要情報を**繰り返し**
- 通知を**抑制**できる

### 自閉スペクトラム (ASD)

社会的合図・比喩・予測困難:
- 比喩・婉曲表現が文字通り取れる
- 急な変更で混乱
- 予測可能性を求める

設計:
- **直接的な言葉**
- 比喩・皮肉を避ける
- 変更前の**事前通知**
- 操作の結果を**事前に**明示

### 認知症 / 高齢

記憶・処理速度・新規学習の低下:
- 短期記憶が弱い
- 多段階フローが困難
- 「**戻る**」を頻繁に間違える

設計:
- ステップを**減らす**
- 各画面で**今どこか**明確
- 「**確認**」を多めに
- 大きな文字・ボタン
- 取り消し可能

### 状況的認知負荷

「健常」な人も:
- 急いでいる
- 騒音中
- 疲労
- 育児中
- 運転中

通常 UI で**苦戦**する場合がある。

→ [[Mental-Models]]

## 設計原則

### 1. 言葉のシンプルさ

**Plain Language** (平易な言葉):

```
✗ "当該リクエストは現在処理中であり、完了次第ご通知申し上げます"
✓ "リクエストを処理中です。完了したらお知らせします"
```

中学生でも分かる語彙。専門用語は**説明併記**。

→ [[UX-Writing]]

### 2. 文の長さ

```
✗ 「複数の条件を満たした上で...」(50 字以上の 1 文)
✓ 「次の条件を満たすと...」(短文 + 箇条書き)
```

### 3. 視覚的階層

→ [[../20-Design/Visual-Hierarchy]]

- 1 画面 = 1 主要アクション
- 重要は**大きく**
- 関連は**近くに**

### 4. 一貫性

予測可能性が**ある**こと:
- ボタンの位置が**ページ間で同じ**
- 色の意味が**全画面で同じ**
- 戻るは**常に左上**

### 5. エラー予防

→ [[Forms-and-Input]]

- 確認ダイアログ
- 入力中バリデーション (blur 時)
- スマートデフォルト
- 「Are you sure?」(不可逆操作)

### 6. 取り消し可能

→ [[Interaction-Patterns]]

「**間違えても直せる**」が認知の安心:
- Undo (Cmd+Z)
- ゴミ箱・履歴
- 自動保存

### 7. 認知負荷の削減

→ [[Mental-Models#認知負荷の-3-種]]

- Hick の法則: 選択肢を減らす
- Miller の法則: 7±2 項目
- 認識 > 記憶: 思い出させず選ばせる

### 8. 進捗の可視化

```
[ Step 2 of 5: 連絡先情報 ]
[━━━●○○○○]
```

「**残り何ステップ**」が見える。
長いフローは**自動保存** + 「**後で続ける**」。

→ [[Onboarding-Empty-States]]

### 9. 多モーダル冗長

情報を**複数チャネル**で:
- 色 + アイコン + テキスト
- 視覚 + 音(必要なら)
- 静止 + アニメ

1 モーダルが**苦手な人**にも届く。

### 10. ユーザーペース

ユーザーが**急かされない**:
- 自動進行を避ける
- タイムアウトの**延長機能**
- 動画の**一時停止 / 速度調整**

## 具体的なパターン

### 入力支援

```html
<label for="phone">電話番号</label>
<input id="phone" type="tel" placeholder="090-1234-5678"
       aria-describedby="phone-hint" />
<p id="phone-hint">ハイフン (-) を入れても入れなくても OK です</p>
```

「形式が違う」だけで弾く → 認知負荷 + 怒り。**寛容**に。

### Reading Mode

長文は**集中モード**を提供:
- サイドバー消去
- 行幅 65 字
- 大きめフォント
- ダークモード / セピア
- 文字サイズ調整

Safari Reader, Medium のリーダー機能が好例。

### 注意の喚起

重要情報は**目立つ場所**に:

```
⚠ 重要: この操作は取り消せません

[ 削除する ] [ キャンセル ]
```

色 + アイコン + テキスト + 配置で**多重に**強調。

### タイムアウト

```
このセッションはあと 5 分で終了します
[ 延長する ] [ ログアウト ]
```

「**気付かないうちに切れた**」を防ぐ。
WCAG 2.5: タイムアウトは延長可能・無効化可能であるべき。

### 「分かりにくい」と感じた時の脱出

```
[ ヘルプ ]    [ サポートに問合せ ]
```

詰まったときに**すぐ助けにアクセス**できる。

## 視覚過敏 (Sensory Sensitivity)

→ [[../20-Design/Motion-System]] / [[Scroll-Driven-Animations]]

- `prefers-reduced-motion` で動きを停止
- パララックスを抑える
- 自動再生動画を**避ける**
- 点滅は**3 回/秒以下** (光感受性発作対応)
- 高コントラストモード対応

## 読み上げの最適化

→ [[Accessibility]]

スクリーンリーダーで読み上げると**疲れる**:
- 余計な装飾を `aria-hidden`
- 「クリック」「ボタン」の重複を避ける
- 読み上げ順序が**論理的**
- スキップリンク

## 言語の補助

### 翻訳

→ [[../40-Bridge/Internationalization]]

母語以外で使うユーザー:
- 機械翻訳ボタン
- ふりがな (日本語)
- 用語集リンク

### 音声入力 / 読み上げ

→ [[Audio-Voice-UX]]

文字入力が困難な人に**音声**選択肢。

## チーム・組織

- 多様な被験者でテスト
- アクセシビリティ専任 (大規模)
- 設計レビューに**認知配慮**観点
- 法的監査 (ADA, EAA 等)

## 法規制

- **EAA** (EU Accessibility Act, 2025-): EU 市場のデジタルサービスは認知配慮含む
- **ADA** (米): 民事訴訟リスク
- **JIS X 8341-3** (日本)
- 認知障害固有の規制も拡大中

## 計測

- タスク完了率 (障害グループ別)
- エラー数
- 時間
- 「**諦めた**」率
- 当事者ユーザビリティテスト

「**できる**」だけでなく「**ストレスなくできる**」を測る。

## アンチパターン

- 全文 CAPS LOCK (読みづらい、叫んでる感)
- 文字を**画像で**配置 (拡大できない、SR で読めない)
- 専門用語の連発
- 多段階フローで**進捗なし**
- タイムアウト**強制**
- 動きで注意を奪う
- エラーが**何が悪いか分からない**
- 「Are you sure?」を毎クリックで(逆に疲れる)

## チェックリスト

- [ ] 言葉が**中学生レベル**で書かれているか
- [ ] 文・段落が**短い**か
- [ ] フローのステップが**最小化**されているか
- [ ] 進捗・現在地が**常に分かる**か
- [ ] **取り消し可能**な操作になっているか
- [ ] エラー予防 + 復旧支援があるか
- [ ] **タイムアウト**が延長可能か
- [ ] `prefers-reduced-motion` を尊重しているか
- [ ] 当事者を含めて**テスト**したか
