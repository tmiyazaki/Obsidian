# 会話型 UI (Conversational UI)

## 一行で

> 「**選ぶ**」UI から「**話す**」UI へ。文脈・履歴・回り道・誤解を**前提**にする設計。

## なぜ重要か

LLM の登場で会話型 UI は爆発的に普及しました。しかし「**チャット欄を置く**」だけでは:
- 何を聞けばいいか分からない (空白の威圧)
- 文脈が**会話を超えて**続かない
- スクロール地獄
- 重要操作の確証が薄い

会話型 UI は**新しい設計パラダイム**であり、ボタン UI とは別の語彙が要る。
→ [[AI-LLM-Interfaces]] (LLM 固有の論点)

## 会話型 UI の種類

### 1. オープン会話 (チャット)

ChatGPT 型。何でも聞ける。最も自由度高い + 最も難しい。

### 2. 制約付き会話 (ボット)

決まったフロー(問い合わせ、予約など)を**会話で**進める。
クイックリプライボタンで誤解を減らす。

### 3. インライン補完

Gmail Smart Compose, GitHub Copilot。**会話せず**にユーザー入力を補完。

### 4. コマンドパレット (Cmd+K)

「次に何をしたいか**自然文 or キーワード**」で受け付ける。
Linear, Slack, Raycast の主要操作インターフェース。

### 5. ボイスエージェント

→ [[Audio-Voice-UX]]

## 会話 UI の設計要素

### メッセージレイアウト

```
[ アシスタント ]
ファイルを要約しました。主要なポイントは…

[ ユーザー ]
詳細を表で整理してください

[ アシスタント ]
| 項目 | 値 |
| ... | ... |
```

- 左右で**話者を区別**(色 + アイコン)
- 順序は**新→旧**(下スクロール)
- 長文は**折りたたみ**可能

### Markdown レンダリング

→ [[AI-LLM-Interfaces]]

- 見出し、リスト、コード、表、リンク
- コードブロックは Syntax Highlight + コピー
- 数式 (KaTeX)、図 (Mermaid) も拡張可能

### ストリーミング表示

タイプライタ風に1文字ずつ:
- 待ち時間の体感短縮
- 途中でキャンセル可能
- スクロールが**勝手に追従**(下にいる時だけ)

## サジェストとプリセット

空白の入力欄は怖い。**よくある質問**を入口に:

```
[ なぜ XX なのか説明 ]   [ 表に整理 ]   [ 短く要約 ]

[ ___________________________ ]
```

新規ユーザーが**何ができるか**を学ぶ。

→ [[Onboarding-Empty-States]]

## 文脈管理

### 1. 会話の履歴

- 各会話を**サイドバー**でリスト
- タイトル自動生成(初回メッセージから)
- 検索可能 → [[Search-UX]]
- 削除・名前変更
- 共有可能(URL)

### 2. システムプロンプトの可視化

ユーザーが**何の文脈**で話しているか分かる:
- 「あなたは Obsidian Vault のアシスタント」と冒頭に明示
- カスタムインストラクションを**設定で**変更可能 → [[Settings-Preferences]]

### 3. 添付・参照

ファイル・URL・メモを**会話に持ち込む**:
- ドラッグ&ドロップ
- @mention で過去会話を参照
- "ナレッジベース" / RAG 統合

### 4. メモリ (長期文脈)

ユーザーの好み・繰り返し情報を**会話を超えて**保持:
- 「次回も同じ形式で」
- ユーザー名・職業・好み
- いつでも**確認・削除可能**

→ [[../40-Bridge/Privacy-by-Design]]

## 入力モード

### テキスト入力

- マルチライン (Shift+Enter で改行、Enter で送信)
- 文字数カウント(LLM のトークン上限警告)
- 添付ボタン
- 音声入力ボタン → [[Audio-Voice-UX]]

### スラッシュコマンド

```
/explain ─ 詳細説明
/translate ja ─ 日本語に翻訳
/summarize ─ 要約
```

「特定モード」を**素早く**指定。プログラム的な入力。

### クイックリプライ

ボット応答に**選択肢ボタン**:

```
ご注文について

[ 配送状況を確認 ]  [ 返品したい ]  [ オペレーターと話す ]
```

「**何を答えればいいか**」が明確。誤解が減る。

## ツール統合 (Function Calling / Tools)

LLM が**外部ツールを呼ぶ**(検索、API、計算機):

```
ユーザー: 東京の天気は?
LLM: [tool: get_weather("Tokyo")]
LLM (ツール結果を受けて): 今日の東京は晴れ、気温は…
```

UI で見せ方:
- ツール実行を**進捗表示**(`🔧 天気を取得中...`)
- 結果を**カード**で表示(リッチな見た目)
- 失敗時は**代替提案**

## エラーと誤解の処理

### 1. 「分からない」を許す

LLM は**自信ありげに誤答**しがち。UX で和らげる:
- 「不明な場合は『不明』と答えて」をシステムプロンプトに
- 出典がない情報は**警告アイコン**
- ユーザーが**訂正**できる("いや、X じゃなくて Y")

### 2. 訂正のインタラクション

```
[ 編集 ]  [ 別の答えを生成 ]  [ 👎 ダメだった ]
```

応答ごとに**編集 / 再生成 / 評価**を提供。

### 3. 文脈リセット

「**新しい会話**」ボタンで前提を**リセット**。長い会話で混乱した時の脱出口。

### 4. 安全装置

危険な操作 (削除・送金・送信) は会話で**直接実行しない**:

```
"このメールを送信しました" ✗ (勝手にやってる)

"以下のメール案を作成しました。送信してよろしいですか?
 [ 送信 ]  [ 編集 ]"  ✓ (人間が決定)
```

→ [[../40-Bridge/Ethical-Design]]

## アクセシビリティ

→ [[Accessibility]]

- 各メッセージに `role="article"`
- ストリーミング中は `aria-live="polite"`
- スクリーンリーダー向けにメッセージの**話者**を読み上げ
- キーボードのみで送信・編集
- 文字サイズ拡大に対応

## モバイル

→ [[Mobile-Patterns]]

- メッセージ入力フィールドは**画面下に固定**
- ソフトキーボード表示時に**最新メッセージが見える**位置に
- 添付・音声入力は**親指届く距離**に
- 長文応答は**折りたたみ**でスクロール疲労軽減

## パフォーマンス

→ [[../10-Coding/Performance]]

- 過去メッセージを**仮想スクロール**(数百件超は重い)
- 画像生成・コード実行は**段階表示**
- ストリーミングは**chunk バッファリング**で滑らかに

## プライバシー

→ [[../40-Bridge/Privacy-by-Design]]

- 会話が**学習に使われるか**を明示
- 機密情報の**自動マスク**(送信前に)
- 削除権 (会話を完全消去できる)

## 会話 UI の限界

会話で何でもできるわけではない:
- **大量データの一覧** → テーブル/リスト UI に勝てない
- **同時に複数操作** → ダッシュボード
- **正確な選択** (日付・色) → 専用ピッカー
- **空間的配置** → 直接操作

「**会話 + 通常 UI**」のハイブリッドが現実解。会話で何でも置き換えようとしない。

## アンチパターン

- 空白の入力欄だけ
- スクロールが**ジャンプ**して読みにくい
- ストリーミング中に**割り込めない**
- 訂正できない
- 危険な操作を**自動実行**
- 会話履歴が**消えて**戻れない
- 全ユーザー操作を**会話で**(普通の UI のほうが早い場面で)

## チェックリスト

- [ ] サジェスト / プリセットで**開始しやすい**か
- [ ] ストリーミング + キャンセル可能か
- [ ] **訂正・再生成**ボタンがあるか
- [ ] 危険操作に**人間の確認**が要るか
- [ ] 文脈が**会話を超えて**保持されるか(必要時)
- [ ] アクセシビリティ (aria-live, キーボード) を満たすか
- [ ] 「**会話以外の UI**」と組み合わせているか
