# AI / LLM インターフェース設計

## 一行で

> 「**確率的で・遅く・たまに間違える**」エージェントを、ユーザーが**信頼して使える形**に翻訳する設計。決定論的 UI とは別のルールで動く。

## なぜ重要か

LLM は「**機能**」ではなく「**新しい入力モード**」です。従来の UI が**選択** (クリック・タップ) を受け付けるのに対し、LLM UI は**意図** (自然言語) を受け付ける。設計の前提が変わります:

- 出力が**毎回違う** (再現性低)
- **遅い** (秒〜十数秒)
- **誤る** (幻覚 / 範囲外応答)
- **コスト**がかかる (トークン課金)

これらを前提に UX を設計しなければ、ユーザーは**信頼を失い**離脱する。

## AI を組み込む 3 つの形

### 1. アシスタント (チャット)

ChatGPT 型。会話で何でもできるが、**新規ユーザーには空白の入力欄**が威圧的。

### 2. インライン (Embedded)

既存 UI に**部分的に**埋め込む。Notion AI, Gmail Smart Compose, Copilot 補完。
ユーザーは「AI を使っている」を意識せず**普通の操作**として体験。

### 3. エージェント (Autonomous)

タスクを与えると**自律的に**複数ステップ実行。Devin, AutoGPT。
進捗の可視化と**人間の介入点**設計が要。

多くのプロダクトでは **インライン > アシスタント** が刺さる。空白入力欄より「次の段落を書く」「ファイルを要約する」が具体的に役立つ。

## 入力設計

### Prompt Template (見えない足場)

ユーザーが書くのは「要約して」だけ。システム側が**コンテキスト・トーン・制約**を組み立てる:

```
[システムプロンプト]
あなたは Obsidian Vault のアシスタント。
ユーザーの語彙: {ubiquitousLanguage}
書記ポリシー: {writingPolicy}
[ユーザーの入力]
"このノートを要約して"
[コンテキスト]
{currentNoteContent}
```

ユーザーから見えない**足場**で品質を底上げ。

### サジェストとプリセット

空白の入力欄は怖い。**よくある依頼**を提案:

```
[ なぜ XX なのか説明 ]   [ 表に整理 ]   [ 短く要約 ]
[ ___________________________ ]
```

ユーザーが**何ができるか**を学ぶための入口。

### スロット (Variables)

「{file} を {format} で出力して」のような部分置換テンプレートで、自由テキストと UI 操作のハイブリッド。

## 出力設計

### ストリーミング

長い応答は**1 文字ずつ**ストリーミング。
- 1 秒待ちが**永遠に感じる**のを防ぐ
- 途中で「これは違う」と気づいて**キャンセル**できる
- フィードバックを**継続的に**返している感覚

技術: Server-Sent Events / WebSocket / fetch streams。

### 引用と根拠

「**この情報はどこから?**」をクリック可能に。
- RAG (検索拡張) の場合は**ソース URL を併記**
- AI が判断した根拠を**短く**表示

幻覚 (Hallucination) のリスクを下げる最も実用的な手段。

### Markdown / 構造化出力

LLM の応答は**Markdown** が基本。表・コード・リスト・見出しが自然に表現できる。
重要なメタデータは **JSON 構造化出力** で受け取り、UI で整形:

```ts
const result = await llm.respond({
  schema: z.object({
    summary: z.string(),
    tags: z.array(z.string()),
    actions: z.array(z.object({ label: z.string(), command: z.string() })),
  }),
});
```

## 信頼の設計

### 1. 不確実性を見せる

```
[ ✨ AI による要約 ]   ← 通常テキストとは別扱い
[ ℹ️ この情報は古い可能性があります ]
[ 🔍 出典を確認 ]
```

ユーザーが「**鵜呑みにしてはいけない**」と理解できる視覚記号。

### 2. 編集可能性

AI 出力をそのまま使う前提でなく、**編集 → 採用**の流れに:

```
AI 提案: "返信案: ..."
[ そのまま送信 ]  [ 編集する ]  [ 別案を見る ]
```

「**人間が最終判断者**」を維持する。

### 3. Undo

AI が大量変更したとき、**1 ボタンで戻せる**ように。Notion AI の "Try again" / "Discard"。

### 4. 透明性

「AI が生成しました」「人間が編集しました」「混合です」を**メタデータ**として保持・表示できる仕組み。EU AI Act ではラベル必須。

## エラーと失敗モード

### 1. 範囲外 (Out-of-scope)

「あなたは X しかできません」と最初から提示。範囲外の要求には**穏やかに断る**:

```
「天気予報には対応していません。
 代わりに、ノートの整理ならお手伝いできます。」
```

### 2. 内容拒否 (Refusal)

機密・違法・倫理的に問題ある要求には拒否。**理由を簡潔に**伝える。

### 3. レート制限 / 課金切れ

ユーザーには「**何が起きていつ復活するか**」を伝える。トークン残量の可視化。

### 4. 沈黙の失敗

「何もしなかった」が最悪。**必ず何か返す**(代替案、待機、人間へエスカレーション)。

## フィードバックループ

```
[👍] [👎]    良かった/悪かった
[ コピー ]   [ 再生成 ]   [ 編集 ]
```

これらのシグナルが学習データになる。**UI から自然に**集める。

「悪かった」をクリックされたとき、**何が悪かったか**(不正確 / 長すぎ / 関係ない / 安全でない)を**選択肢**で取ると改善が早い。

## レイテンシとコストの UX

### 計算結果が遅いとき

- スケルトン → ストリーミング表示
- バックグラウンド実行 + 通知 (`完了したらお知らせします`)
- キャッシュ (同じ質問は再計算しない)

→ [[Loading-States]]

### 課金の透明性

- 残り回数 / トークンを表示
- **重い操作**は事前に確認 (`これは X トークン使用します。続けますか?`)
- プランアップグレード導線

## マルチモーダル

画像 + テキスト, 音声 + テキスト ── モードを混ぜる UI。
- ドラッグ&ドロップで画像を入力に
- 音声入力 (`Whisper` 等) → テキスト → 編集 → 送信
- カメラからリアルタイム解析

各モードに**フォールバック** (テキストでも入力可能) を必ず提供。

## エージェント設計の論点

### 1. 自律性のレベル

```
L0: 提案のみ (人が選ぶ)
L1: 確認後実行
L2: 自動実行 + 通知
L3: 完全自律 (例外時のみ通知)
```

リスクが高い操作 (送信・支払い・削除) は L1 以上にしない。

### 2. 進捗の可視化

```
[ ✓ ファイルを検索 ]
[ ✓ 変更内容を分析 ]
[ ⏳ レポート生成中... ]
```

何ステップあって今どこか、ユーザーが把握できる。

### 3. 介入点

「ここで人の確認が要る」を**明示**:

```
[ AI が変更を提案しました ]
[ レビュー ]  [ そのまま実行 ]  [ キャンセル ]
```

## プライバシーと安全

→ [[Security]] / [[../40-Bridge/Ethical-Design]]

- **データ送信先**を明示 (ローカル LLM か API か)
- **機密情報のフィルタ**(送信前にマスク)
- **学習に使われるか**を選択可能 (オプトアウト)
- ユーザーがアップロードした内容の**保存期間**を明示

## アクセシビリティ

→ [[Accessibility]]

- スクリーンリーダーで AI 出力が**読み上げ可能**
- ストリーミング中の `aria-live` 通知 (うるさすぎないように)
- 音声入力代替 (キーボード)
- 認知負荷: 長すぎる出力は折りたたみ

## アンチパターン

- 入力欄だけ置いて「何でもできます」(空白の威圧)
- 出典なしの**確信ありげな**生成
- 全ユーザー操作を AI で置き換える (UI が悪化)
- 訂正不能な自動実行 (Undo なし)
- 進捗不明で**長時間沈黙**
- 「AI 搭載!」をアピールするだけで使い道が薄い
- 無料枠の境界が**操作中に**判明する

## チェックリスト

- [ ] AI 出力に**視覚的識別子**があるか
- [ ] 出典・根拠が**確認可能**か
- [ ] **編集 / Undo** が常に可能か
- [ ] ストリーミングで**応答性**を出しているか
- [ ] 失敗時に**何ができるか**を提示しているか
- [ ] フィードバックボタン (👍👎) があるか
- [ ] プライバシーが**透明**か
- [ ] 課金 / レート制限が**事前に**伝わるか
