# ウェアラブル / TV / 組み込み UI

## 一行で

> モバイル・デスクトップだけが UI ではない。**腕・テレビ・キオスク・車載・家電** ── それぞれ違う**操作・距離・時間**で設計が変わる。

## なぜ重要か

UI 設計の語彙はモバイル/デスクトップに偏っています。しかし:
- **Apple Watch / Wear OS** ─ 腕の上の数秒
- **Apple TV / Android TV** ─ 5m 先、リモコン操作
- **キオスク・ATM** ─ 公共空間、立ち姿勢
- **車載** ─ 安全第一、視線を奪わない
- **冷蔵庫・電子レンジ** ─ ボタンと小画面

各々のコンテキストに**別の設計言語**が必要。

## ウェアラブル (Watch)

### 文脈

- **数秒の使用**(チラ見)
- 腕は不安定、画面小、片手
- センサー豊富 (心拍・歩数・GPS)
- 通知の入口

### 設計指針

- **1 画面 = 1 アクション**
- 文字大、タップ領域大 (最低 44×44)
- 階層浅く(3 階層以内)
- 縦スクロール(横は無理)
- 入力はほぼ**音声**または**プリセット**

### 主要パターン

#### Glance (一目)

```
[ 心拍 92 bpm ]
[ 8,432 歩 / 10,000 ]
[ 12:34 PM ]
```

文字盤や通知センターで**一瞬で読める**情報。

#### コンプリケーション

文字盤に置けるミニウィジェット (温度、次の予定、バッテリー)。常に見える情報。

#### 短い操作

- 通知への返信(音声 or 定型)
- 1 タップでタイマー開始
- 心拍を測る

### ハプティクス

→ [[Sensor-Camera-Haptics]]

腕の上では**触覚**が重要:
- メッセージ受信を振動で知らせる
- ナビ「**右に振動 = 右折**」
- 心拍異常を**強い振動**で警告

### ヘルス・フィットネス

- 連続計測のバッテリー管理
- 警告 (異常心拍、転倒)
- 月単位のグラフ → モバイル/Web で詳細

### 主要プラットフォーム

- watchOS (Apple Watch)
- Wear OS (Google)
- Garmin Connect IQ
- Fitbit

各ガイドラインを参照(画面サイズ、入力モード、HIG)。

## TV (10-foot UX)

### 文脈

- **3〜5m** 先から見る
- リモコン (D-pad + Select)、たまに音声
- 横長 (16:9)、暗い部屋
- 複数人で見る

### 設計指針

- 文字は**画面比 2-3% 以上** (700×30px etc.)
- 高コントラスト + シャドウ (背景動画でも読める)
- フォーカスがどこにあるか**強調**(明らかな枠 / スケール)
- **セーフエリア**(画面端 5% は表示しない、TV のオーバースキャン)

### ナビゲーション

- 縦/横の**カードグリッド**(Netflix, Apple TV)
- D-pad で**フォーカス移動**
- 「決定」で開く、「戻る」で前へ
- 横スワイプで**カテゴリ切替**

### フォーカス管理

```css
.card {
  transition: transform 0.2s, box-shadow 0.2s;
}
.card:focus {
  transform: scale(1.05);
  box-shadow: 0 0 0 4px var(--accent);
  z-index: 10;
}
```

D-pad のフォーカス追従はライブラリ (`react-spatial-navigation` 等) で楽になる。

### 動画再生

→ [[Video-Motion-Graphics]]

- 全画面再生
- リモコンで一時停止 / シーク / 字幕
- Picture-in-Picture
- スリープモードからの復帰

### 入力

- リモコン入力は**遅い**。長文入力は**スマホ連携** (Apple TV Remote App)
- 音声検索 (Hey Siri, Google Assistant)
- 文字入力は**最小限**(ログイン QR 生成等で回避)

### 主要プラットフォーム

- tvOS (Apple TV)
- Android TV / Google TV
- Roku
- Fire TV
- Tizen (Samsung), webOS (LG)

クロスプラットフォームには **Web ベース (HTML5 Video + 各社拡張)** がよく使われる。

## キオスク・公共端末

### 文脈

- 立ち姿勢、短時間
- **タッチ前提**(マウス/キーボードなし)
- 騒がしい環境
- 不特定多数(プライバシー・衛生)

### 設計指針

- 大きなボタン、太い文字
- アイコン + 短文の組合せ
- **言語切替**を常に上部に
- アクセシビリティ(車椅子の高さ、視覚補助、聴覚補助)
- **タイムアウトでホーム**に戻る(前ユーザーの情報を残さない)
- スクリーンキーボード(QWERTY 配列)

### セキュリティ・プライバシー

- 決済情報はその場で**消去**
- 印刷物に **個人情報を出さない**
- カメラがある場合の**録画告知**

### 例

- ATM
- 自動チェックイン (空港)
- セルフレジ
- 美術館の案内端末

## 車載 (Automotive)

### 文脈

- **運転中の使用**(視線奪取は危険)
- 短時間の操作
- 騒音環境(音声重視)
- 規制 (各国の安全基準)

### 設計指針

- **音声操作**を主軸 (Apple CarPlay, Android Auto)
- 視覚要素は**極小限**、コントラスト最大
- ボタン操作は**1 階層**で完結
- アニメーション・装飾は**禁忌**(注意を奪う)
- 走行中は**特定機能を無効化**

### 主要プラットフォーム

- CarPlay (iOS)
- Android Auto / Android Automotive OS
- 各 OEM 独自 (Tesla, Mercedes MBUX, BMW iDrive)

CarPlay/Android Auto は**プラットフォームの規範に従う**(独自 UI を作らせない)。

## 組み込み・家電

### 文脈

- 専用機器 (冷蔵庫・電子レンジ・カメラ)
- 物理ボタン + 小画面
- 入力手段限定
- 電源効率重視

### 設計指針

- **物理ボタンとの一体化**
- メニューは**浅く**(深い階層は迷子)
- 文字は大きく、アニメは最小
- 工場リセットへの導線

### IoT との統合

- スマホアプリで**詳細操作**
- 機器自体は**最小操作**
- Wi-Fi 設定は QR で簡単に
- 故障時の**通知**

## ゲーム機 / VR

→ [[AR-VR-Spatial]]

- ゲームパッド入力
- 没入型 (VR)
- 5m 距離の TV と類似

## 共通の設計原則

### 1. コンテキストファースト

「ユーザーは**今どこで・誰と・何をしながら**この UI を使うか」を先に定義。デスクトップ UI を**そのまま縮小**しない。

### 2. 入力モード固有

タッチ・D-pad・音声・物理ボタン ── 入力で UI が変わる。
キーボードショートカットを TV で見せても**意味がない**。

### 3. 距離

20cm (スマホ) / 60cm (PC) / 3m (TV) / 5m (キオスク)。
**文字サイズ・タップ領域**は距離に比例して大きく。

### 4. 持続時間

数秒 (Watch) / 数分 (Phone) / 数時間 (TV)。
**情報密度と疲労度**で設計。

### 5. プラットフォーム慣習

各 OS のガイドラインを尊重:
- Apple HIG (iOS, watchOS, tvOS, visionOS)
- Material Design (Android, Wear OS, Android Auto)
- Roku / Fire TV / Tizen ガイド

ユーザーは**他のアプリで学んだ操作**を期待する。

## クロスデバイス連続性

ユーザーは**複数デバイスを行き来**する:
- iPhone で記事の途中 → Apple Watch で続き読み
- スマホで動画開始 → TV にキャスト
- PC で文書編集 → スマホで承認

設計の要点:
- 状態を**クラウドで同期**
- デバイス間の**ハンドオフ** (Apple Continuity)
- それぞれで**最適な UI**(変形)
- どのデバイスからも**履歴・進捗**が見える

## アクセシビリティ

→ [[Accessibility]] / [[../40-Bridge/Inclusive-Design]]

- 各プラットフォームの SR (VoiceOver, TalkBack, etc.)
- 大文字 / 高コントラスト設定
- 字幕 (TV)
- 音声操作(運転中・両手塞がり)
- 物理ボタン (タッチ困難ユーザー)

## アンチパターン

- スマホ UI を**そのまま**TV に
- TV のフォーカスが**どこか分からない**
- Watch で**長文入力**を要求
- 車載で**派手アニメ**
- キオスクで**前ユーザーの情報**が残る
- IoT 機器で**スマホ必須**(機器単体で何も設定できない)
- プラットフォーム慣習を**無視**

## チェックリスト

- [ ] **コンテキスト**(距離・時間・入力)が明確か
- [ ] プラットフォーム HIG / ガイドラインに従っているか
- [ ] 入力モードに応じた UI か
- [ ] 文字サイズ・タップ領域が**距離に妥当**か
- [ ] クロスデバイスで**状態が同期**するか
- [ ] アクセシビリティ機能を**そのまま使える**か
- [ ] プライバシー (公共端末・録画告知) が考慮されているか
