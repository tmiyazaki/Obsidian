# UX の基本原則

## 一行で

> UX は「**ユーザーがシステムをどう経験するか**」の設計。**気づき・操作・フィードバック・回復**の 4 局面で考える。

## なぜ重要か

ユーザーは仕様書を読まずに UI を触ります。彼らが頼る情報は「**画面に何が見え、操作してどう反応するか**」だけ。設計者の意図は、**画面という単一のインターフェース**を通して伝わるしかありません。

## ヤコブ・ニールセンの 10 ヒューリスティクス

UI レビューの世界共通言語。覚えておくと議論が早い。

### 1. システム状態の可視性

ユーザーは**今システムが何をしているか**を常に把握できるべき。
- 読み込み中はスピナー、進捗ありなら進捗バー
- 保存完了はチェックマーク
- 検索結果は「N 件中 M 件」

### 2. 現実世界との一致

専門用語を**ユーザーの言葉**で書く。
- ❌ `HTTP 500: Internal Server Error`
- ✅ `サーバーで問題が発生しました。少しあとで試してください。`

### 3. ユーザー制御と自由

「**取り消し**」と「**やり直し**」を提供する。誤操作は**起こる前提**で設計する。
- ファイル削除に Undo
- モーダルは ESC で閉じる
- 不可逆な操作には**確認ダイアログ + 影響範囲の明示**

### 4. 一貫性と標準

同じ意味は同じ表現で。プラットフォーム慣習に従う。
- 「ボタン」と「リンク」を意味で区別(行動 vs 移動)
- 進む = 右、戻る = 左

### 5. エラー予防

**起きてから直す**より、**起きないように作る**ほうが安い。
- 削除前の確認 + 影響説明
- 入力中バリデーション
- 矛盾する選択肢を**選べないように**(無効化)

### 6. 認識 > 記憶

人間の短期記憶は 4±1 アイテム。**思い出す**より**選ぶ**方が易しい。
- 直前の検索キーワードをサジェスト
- 過去のアクションを履歴で見せる
- ナビは閉じずに見せ続ける

### 7. 柔軟性と効率

初心者には案内、熟練者にはショートカット。両立する。
- メニューの操作にキーボードショートカット
- カスタマイズ可能な順序
- Bulk 操作

### 8. ミニマルなデザイン

すべての追加要素は**他要素の重要性を相対的に下げる**。
- 装飾を削る
- 不要なオプションを隠す(段階的開示)
- セクションごとに役割を 1 つに

### 9. エラーからの回復支援

エラーは:
- 何が起きたか
- なぜ起きたか
- 次にすべきこと
を**ユーザーの言葉**で示す。`HTTP 500` は技術者向けログへ。

### 10. ヘルプとドキュメント

- 文脈ヘルプ(`?` アイコンでツールチップ)
- 検索可能なドキュメント
- まずは**ドキュメント不要**の UI を目指す

## ノーマンの「7 段階のアクション」

ユーザーの操作はこの 7 段階を踏んでいる:

```
1. 目標の形成     「何をしたい?」
2. 意図の形成     「どうやる?」
3. 行為の指定     「どう操作する?」
4. 行為の実行     ◎ クリック・入力
5. 結果の知覚     「何が起きた?」
6. 結果の解釈     「どう変わった?」
7. 評価           「目標は達成された?」
```

UX が壊れる場所は「**実行と評価のギャップ (Gulf of Evaluation)**」と「**指定と実行のギャップ (Gulf of Execution)**」。
- 「やりたいこと」を表現する手段が見つからない (Gulf of Execution)
- 操作した結果が**わからない・伝わらない** (Gulf of Evaluation)

両方のギャップを埋めるのがインターフェース設計者の仕事。

## アフォーダンスとシグニファイア

- **アフォーダンス**: 物理的に「**できること**」(ボタンは押せる、ドアは押すか引くか)
- **シグニファイア**: 「**できることを示す手がかり**」(押せそうに見える形、引っ張る形のハンドル)

UI で良くある欠陥:
- フラットデザイン化でボタンに**シグニファイアが消える** → 押せるか分からない
- 「リンクっぽい色付き文字」が**ただの強調**に使われている

両者の混同を避けるため、**ボタン = 高さ・縁・押せそうな質感**、**リンク = 下線**、と決めごとを守る。

## 認知負荷の 3 種

| 種類 | 内容 | 設計指針 |
|---|---|---|
| Intrinsic | 課題本来の難しさ | 構造化・段階化で軽減 |
| Extraneous | 余計な負荷(雑な UI 等) | **削減**する |
| Germane | 学びに繋がる負荷 | 適度に残す |

UX 改善の多くは **Extraneous の削減**。
