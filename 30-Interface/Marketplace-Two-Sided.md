# マーケットプレイス・両面プラットフォーム UX

## 一行で

> 「**売り手と買い手**(または提供者と利用者)」を同時に設計する。片側が**飢える**と全体が崩れる**鶏卵問題**。

## なぜ重要か

両面プラットフォームは:
- メルカリ・ヤフオク (CtoC EC)
- Airbnb (民泊)
- Uber / Lyft (配車)
- Upwork / クラウドワークス (フリーランス)
- Etsy (ハンドメイド)
- App Store (アプリ)
- Substack (出版者と読者)

純粋な BtoC EC とは**根本的に違う**問題:
- 双方の獲得・継続
- マッチング
- 信頼形成
- 取引保証

## 鶏卵問題

```
売り手がいない → 買い手が来ない → 売り手が来ない
```

立ち上げで「**片側を先に増やす**」戦略:

### サプライ先行 (供給優先)

売り手・出品を**先に**集める:
- 在庫が**見える**と買い手が来やすい
- 多くの場合これ
- Airbnb 初期: 創業者がホストを訪問して撮影

### デマンド先行 (需要優先)

買い手を先に集める:
- 「ニーズがある」と売り手が来る
- Substack 初期: 著者は読者がいると見て参加

### Hack 戦略

- 一方を**手動代行**(Concierge MVP)
- 競合からのインポート
- 価格補助
- 地域限定で**密度を確保**
- → [[../40-Bridge/Discovery-and-Validation]]

## UX の設計領域

### 1. 売り手側 (Supply UX)

- 出品フロー
- 価格設定
- 在庫管理
- 受注通知
- 売上ダッシュボード
- 評価・レビュー閲覧
- 振込・出金

→ [[Dashboard-Design]] / [[Forms-and-Input]] / [[Notifications]]

### 2. 買い手側 (Demand UX)

- 検索 / 発見
- フィルタ
- 商品ページ
- カート / 予約
- 決済
- 配送追跡 / 利用
- レビュー投稿

→ [[Search-UX]] / [[Tables-Data-Grids]] / [[Pricing-Monetization-UX]]

### 3. マッチング

```
[ 買い手の条件 ] ←→ [ 売り手の在庫 ]
              ↓
         マッチング
```

- 検索順位 (relevance)
- 推薦 (collaborative filtering)
- リアルタイムマッチ (Uber: 配車要求 → ドライバ割当)
- 自動入札 (オークション)

「**何が上位に出るか**」が**売り手の生死**を握る。

### 4. 信頼・評価システム

両面で**他方を信頼できるか**:

```
売り手評価: ★★★★ (120 件のレビュー)
本人確認:    ✓
利用回数:    52 回
最終取引:    1 日前
```

要素:
- 双方向レビュー
- 本人確認 (KYC)
- 取引履歴
- 認証バッジ
- 苦情・トラブル件数

## レビューシステム

### 双方向 vs 片方向

- Airbnb: ホストとゲスト**両方**を評価
- Amazon: 買い手が**売り手を**評価のみ

双方向は**両側に責任**を与える。

### ブラインドレビュー

両者が書き終わるまで**互いに見えない**:
- 報復評価防止
- 正直な評価

### 評価の公平性

- 取引未成立で評価不可
- 削除フローと**根拠**
- 「**評価返し** (お返しの星)」の検出

## トラブル対応

→ [[Customer-Support-UX]]

- キャンセル (誰が、いつまで)
- 返金 (条件、手数料)
- 詐欺対応
- エスカレーション
- 仲裁

「**安心して使える**」をデザインで支える:
- 取引保証 (購入保護)
- エスクロー (代金預かり)
- 24h サポート

## 検索とランキング

→ [[Search-UX]]

両面 PF の検索は**特殊**:
- 売り手の**手数料**で運営が回る → 売り手のインセンティブ調整
- ロケーション・在庫リアルタイム性
- パーソナライズ
- 公平性 (同じ条件なら平等表示)

```
ランキング要素:
  - 関連度
  - 距離 / 在庫
  - 売り手評価
  - 価格
  - 売り手のロイヤルティ
  - 広告 (transparent labeling 必須)
```

「広告表示」は**ユーザーに明示**(規制)。

## 価格設定

→ [[Pricing-Monetization-UX]]

両面 PF の課金:

### 取引手数料

- Airbnb: 売り手 3% + 買い手 12-15%
- Etsy: 売り手のみ
- App Store: 30% (一部 15%)

### サブスクリプション

- 売り手の月額(店舗運営)
- 買い手のメンバーシップ (Costco 型)

### Listing Fee

- 出品 1 件あたり料金
- 露出量制限

### Dynamic Pricing

需要 / 供給で**自動調整**:
- Uber Surge Pricing
- Airbnb の推奨価格
- オークション

倫理: **災害時の暴騰**は批判の的。規制 (反便乗値上げ法)。

## グロース戦略

### Network Effects (ネットワーク効果)

参加者が増えるほど**価値が指数的**:

```
N 人 → N(N-1)/2 ペア
```

ただし「ローカル」 vs 「グローバル」:
- Uber は**都市単位**(別都市では役立たない)
- LinkedIn は**グローバル**

### 流動性 (Liquidity)

「探したらすぐ見つかる」「出したらすぐ売れる」。
低流動性は離脱を呼ぶ。

### Referral

「友人を招待でクーポン」は両面で:
- 売り手の招待 → 在庫増
- 買い手の招待 → 需要増

## 多言語・多通貨

→ [[../40-Bridge/Internationalization]]

国際マーケットプレイス:
- 配送可能エリア
- 通貨換算
- 関税表示
- 言語別レビュー (翻訳機能)
- 法規制 (販売可能商品が国別に異なる)

## 詐欺・不正対策

→ [[../10-Coding/Security]] / [[../40-Bridge/Privacy-by-Design]]

両面 PF の脅威:
- 偽出品 (見せかけ商品)
- 偽レビュー (買収)
- 偽アカウント (KYC 抜け)
- マネーロンダリング
- 知財侵害 (コピー商品)

対策:
- 機械学習による異常検知
- KYC + AML (Anti-Money Laundering)
- レビュー操作検出 (Amazon, Yelp)
- 報告ボタン + 人手レビュー
- ブロックリスト

→ [[Trust-and-Safety]] (将来ノート)

## モバイル特化

→ [[Mobile-Patterns]]

多くのマーケットプレイスは**モバイル中心**:
- 写真撮影 → 即出品 (メルカリ)
- 位置情報での近所検索 (フリマ)
- プッシュ通知 (新着・落札)
- カメラ + AI で出品支援

## 規制

国・業種で:
- 古物営業法 (中古 EC)
- 旅館業法 (民泊)
- 道路運送法 (配車)
- 食品衛生 (デリバリ)
- 金融商品取引法 (P2P 融資)

「テック企業」を装っても**実体は規制対象**になりうる。Uber が世界中で訴訟。
法律部門と**早期に連携**。

## 透明性

→ [[../40-Bridge/Ethical-Design]]

ユーザーに見せるべき:
- 手数料の**内訳**
- アルゴリズムの**判断基準**(おすすめ / 順位)
- 広告と自然結果の**区別**
- 売り手の**本人性**

EU DSA (Digital Services Act) で大規模 PF に追加義務。

## ダッシュボード

→ [[Dashboard-Design]]

売り手向け:
- 売上 / 注文数
- 評価
- 在庫アラート
- 競合分析(類似商品の価格)
- 出品の改善提案 (AI)

「**自分のビジネスを成長させる**」体験を提供。

## サポート体制

→ [[Customer-Support-UX]]

両面 PF はサポート負荷高:
- セルフサービス (FAQ, AI チャット)
- エスカレーション (人間)
- 仲裁 (両者間)
- 24h 体制 (グローバル PF)

## アンチパターン

- 鶏卵問題を**マーケで解決**しようとして失敗
- 片側に**手厚すぎ**で他方が離れる(Uber の運転手不足)
- レビュー操作を**検出しない**
- 詐欺対応が**手作業**で間に合わない
- アルゴリズムの**不透明性**で不信
- 規制を**無視**して訴訟
- 多言語対応**しない**で国際拡大
- セルフサービスなしで**全件人間対応**

## チェックリスト

- [ ] 両面の**主要 UX フロー**が設計されているか
- [ ] 信頼システム (レビュー・本人確認) があるか
- [ ] 検索・マッチングが**両面の利益**を考慮するか
- [ ] 詐欺・不正検知の**仕組み**があるか
- [ ] アルゴリズムの**透明性**を提供しているか
- [ ] 規制対応 (KYC, 報告義務) を満たすか
- [ ] サポート体制が**スケール**するか
- [ ] 両側のグロース指標を**測っている**か
