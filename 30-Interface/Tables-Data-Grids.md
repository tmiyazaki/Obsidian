# テーブルとデータグリッド

## 一行で

> テーブルは「**行と列**」ではなく「**比較・操作・スキャン**を可能にする情報密度の高い UI」。 業務 SaaS の主役。

## なぜ重要か

業務系/管理系プロダクトの**主要画面の半分以上**はテーブル/リスト。データ件数・列数・操作種類が増えると複雑度が指数的に増し、最も**作り込みが必要な UI** の一つです。雑なテーブルは:
- スキャンできない (重要列が埋もれる)
- 操作できない (1 行ずつしか動かせない)
- 拡張しにくい (列追加で破綻)

## 5 つの設計判断

### 1. データの性質

| 件数 | 推奨 |
|---|---|
| 5〜30 件 | 普通のテーブル |
| 30〜500 件 | + ソート・フィルタ |
| 500〜10K | + ページネーション、サーバーサイド処理 |
| 10K+ | + 仮想スクロール、検索専用 UI |

### 2. 列の優先度

すべての列を等しく扱わない。**主要 3〜5 列**を見せ、残りは:
- 横スクロール
- 列の表示/非表示トグル
- 詳細パネル (行クリックで展開)

### 3. 比較 vs 一覧 vs 編集

- **比較**: 2 件を並べて違いを見る → カラム整列、差分強調
- **一覧**: ざっと俯瞰 → 階層、グルーピング
- **編集**: 値を変える → インライン編集、選択操作

主たる目的によって UI 方針が変わる。

### 4. 行の意味

行は「**1 つのリソース**」 ─ 1 ユーザー、1 注文、1 タスク。
集約行 (合計、平均) は**色やボーダー**で区別。

### 5. 画面サイズ

モバイルでは伝統的テーブルは破綻する。**カードリストへの変形**が必要 (後述)。

## 視覚設計の原則

### 横線より縦のリズム

```
❌ 行ごとに横線 → 牢屋っぽい
✅ 行内パディングと交互の薄背景 (zebra)
```

ただし zebra も多用するとうるさい。**ホバー時に行を強調**するほうが控えめで効く。

### 列幅の決定

- 短い文字列 (ID、ステータス): 内容に合わせ**狭く固定**
- 長い文字列 (名前、説明): **可変**
- 数値: **右寄せ + 等幅数字 (`tabular-nums`)** で桁揃え

```css
td.number { font-variant-numeric: tabular-nums; text-align: right; }
```

### 数値の整形

```
1,234,567        ← 桁区切り
¥1,234           ← 通貨
2026-05-02       ← 日付 ISO
2 時間前          ← 相対時間
```

→ [[../40-Bridge/Internationalization]] の `Intl` API を使う。

### 列ヘッダ

- 短く明確 (動詞でなく名詞)
- ソート可能なら矢印アイコンを表示
- ホバーで完全名 (`tooltip`) も可
- スティッキー (固定) で長いテーブルでも見える

```css
th { position: sticky; top: 0; background: var(--surface); }
```

### 整列

- 文字: 左
- 数値: 右
- アイコン・ステータス: 中央 (短いとき)

## 主要機能

### ソート

- クリックで昇順 → 降順 → 解除
- アイコンで現在の状態を表示
- マルチカラムソート (Shift + クリック) は**応用機能**

### フィルタとファセット

- 列ヘッダのアイコンから (Excel 風)
- 上部の専用バー
- 高度な絞り込みは別パネル
- 結果数を**即時表示**: `42 件中 3 件`

### 検索

→ [[Search-UX]]

### ページネーション vs 無限スクロール vs 仮想スクロール

| | 強み | 弱み |
|---|---|---|
| ページネーション | 戻る/共有が楽、フッタ可視 | 連続閲覧で操作が増える |
| 無限スクロール | 連続閲覧楽 | 戻れない、フッタ不可視、SEO 弱 |
| 仮想スクロール | 大量データに耐える | アクセシビリティ・印刷で苦労 |

業務系は**ページネーション**が標準。フィードは**無限スクロール**。1万件以上は**仮想スクロール**。

### 行の選択

- **チェックボックス**で複数選択
- ヘッダのチェックで「全選択」(画面分か全件分かを明示)
- 選択中はバルク操作バーが**フローティング表示**

```
[ ✓ 5 件選択中 ]   [ 削除 ]  [ エクスポート ]  [ ✕ 解除 ]
```

### バルク操作

- 削除、ステータス変更、エクスポート、タグ付け
- 影響範囲を**確認ダイアログ**で明示 (5 件か、全件か)
- Undo を提供

### インライン編集

- セルクリックで編集モード
- Enter で確定、Esc で取消
- バリデーションは**保存時**または**フォーカス離脱時**
- サーバ更新中はスケルトン (Optimistic UI を避ける場合)

複雑な編集は**モーダル or サイドパネル**へ。

### 列のカスタマイズ

- 表示/非表示
- 並べ替え (drag & drop)
- 幅変更 (リサイザ)
- 設定の保存 (ローカル or サーバ)

## モバイル対応

### カードリストへの変形

```
[ Avatar | Name        ]
        [ Status        ]
        [ Updated       ]
[ Avatar | Name        ]
        [ Status        ]
        [ Updated       ]
```

横スクロールではなく、**カード化**。重要列を上に、補足を下に。

### 主要操作だけに絞る

モバイルで「ソート・フィルタ・全列表示」を再現すると破綻。
- 検索だけ提供
- 詳細は **Drawer** で開く
- バルク操作は省略 (デスクトップで)

## アクセシビリティ

- セマンティック HTML: `<table>`, `<thead>`, `<th scope="col">`
- ヘッダと値の関連付け
- ソートボタンに `aria-sort="ascending"`
- スクリーンリーダーで「N 行 M 列のテーブル」アナウンス
- キーボードでセル間移動 (矢印キー)

```html
<table>
  <caption>注文一覧 - 42 件</caption>
  <thead>
    <tr>
      <th scope="col" aria-sort="ascending">日時</th>
      <th scope="col">顧客</th>
      <th scope="col">金額</th>
    </tr>
  </thead>
  <tbody>...</tbody>
</table>
```

→ [[Accessibility]]

## パフォーマンス

→ [[../10-Coding/Performance]]

- 仮想スクロール (TanStack Virtual, react-window)
- メモ化 (React.memo, useMemo)
- ソート/フィルタは**サーバ側**に
- 重いセル (チャート埋め込み等) は**遅延描画**

## 実装ライブラリ

- **TanStack Table** (旧 React Table): ヘッドレス、最も柔軟
- **AG Grid**: エンタープライズ機能満載 (Excel 風)、商用
- **MUI DataGrid**: Material 系
- **Glide Data Grid**: キャンバスベース、超大量データ
- **Handsontable**: スプレッドシート風

要件に応じて。**自作を最後まで避ける**ほうが時間の節約になる場合が多い。

## 空状態 / エラー / ロード

→ [[Loading-States]] / [[Onboarding-Empty-States]]

- **空 (検索結果ゼロ)**: 「もしかして」「フィルタを緩める」
- **空 (初回)**: 「最初の N を作成」
- **ロード**: スケルトン (列数・行数を予約)
- **エラー**: 「再試行」ボタン

## アンチパターン

- 全列等幅で**重要情報が埋もれる**
- 横スクロールでヘッダが**消える** (sticky なし)
- ページネーションが「<」「>」だけ (現在ページ・総数なし)
- バルク選択した後の**操作が見つからない**
- Excel ライクな**過剰機能**で学習困難
- モバイルで**横スクロール**地獄
- 数値が左寄せで**桁が読めない**
- ソートしたら**スクロール位置が消える**

## チェックリスト

- [ ] 主要列が**3〜5 列**に絞れているか
- [ ] 数値が**右寄せ・桁揃え**か
- [ ] ソート・フィルタの**現在状態**が見えるか
- [ ] バルク選択時の**操作バー**が表示されるか
- [ ] スティッキーヘッダで**長いテーブルでも見える**か
- [ ] モバイルで**カード変形**しているか
- [ ] アクセシビリティ (semantic HTML, aria-sort) を満たすか
- [ ] **空・ロード・エラー**状態が設計されているか
