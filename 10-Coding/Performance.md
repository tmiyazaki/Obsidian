# パフォーマンス最適化

## 一行で

> **計測してから最適化する**。推測は外れる。最適化は「速くすること」ではなく「**ボトルネックを移動させること**」である。

## なぜ重要か

> "Premature optimization is the root of all evil." — Donald Knuth

しかし**遅すぎるアプリは UX を破壊する**。読み込み 3 秒の遅延で離脱率は跳ね上がり、入力レイテンシが 100ms を超えると操作感が断絶します。性能は **UX の構成要素**です(→ [[../40-Bridge/Performance-as-UX]])。

## 順序: Measure → Hypothesize → Change → Verify

1. **Measure**: プロファイラで真のボトルネックを特定
2. **Hypothesize**: 「ここが遅い理由は X だろう」を仮説化
3. **Change**: 最小変更を入れる
4. **Verify**: 再計測して仮説を検証(逆効果なら戻す)

直感での最適化は半分以上が**役に立たないか悪化する**。

## 階層的なコスト構造(目安)

| 操作 | おおよそのレイテンシ |
|---|---|
| L1 キャッシュ参照 | ~1 ns |
| L2 キャッシュ参照 | ~5 ns |
| メインメモリ参照 | ~100 ns |
| SSD ランダム読み | ~100 µs |
| データセンター内 RTT | ~500 µs |
| 大陸間 RTT | ~150 ms |

→ **メモリ局所性 (locality)** はアルゴリズム計算量より効くことがある。連続したメモリを舐めるのと飛び飛びでは数十倍の差。

## 最適化パターン

### 1. アルゴリズム改善

最大効果は依然 O(n²) → O(n log n) のような**計算量の改善**。データ規模が増えるほど効く。

### 2. キャッシュ

```
原則:
- 強い不変条件のあるデータをキャッシュ
- 無効化戦略を先に決める(TTL? イベント駆動?)
- ヒット率を計測する
```

キャッシュは万能薬ではない:
- **整合性問題**: 古いデータを返すリスク
- **キャッシュスタンピード**: 期限切れ瞬間に同時再生成 → 下流が落ちる
- **メモリ圧迫**

### 3. バッチ・並列

- N+1 クエリ → JOIN または `WHERE id IN (...)`
- 直列 await のループ → `Promise.all` で並列(ただし下流のレートリミットに注意)
- バックエンドの大量処理 → ジョブキュー化

### 4. 遅延化 (Lazy)

- 起動時に全部読まず、必要時に読む(コードスプリッティング、画像の lazy load)
- React: `Suspense`, dynamic import

### 5. プリロード・プリフェッチ

- ナビゲーション直前にデータを取りに行く
- 次ページ候補を idle 時に取得

### 6. データ局所性

- AoS (Array of Structs) よりも SoS / SoA(Struct of Arrays)が刺さる場面がある
- Hot path で大きなオブジェクトを丸ごと回さない

## フロントエンド固有

### Core Web Vitals

| 指標 | 意味 | 目標 |
|---|---|---|
| **LCP** (Largest Contentful Paint) | 主要コンテンツ表示まで | < 2.5s |
| **INP** (Interaction to Next Paint) | 入力応答 | < 200ms |
| **CLS** (Cumulative Layout Shift) | レイアウトの飛び | < 0.1 |

### 主要技法

- **画像**: 適切なフォーマット(AVIF/WebP)、寸法属性、`loading="lazy"`、`srcset`
- **JS**: コードスプリッティング、不要ライブラリ削除、ハイドレーションを必要箇所だけに
- **CSS**: critical CSS をインライン、未使用 CSS の除去
- **フォント**: `font-display: swap`、サブセット化、preload
- **第三者スクリプト**: 計測の名のもとに肥大化しがち、必要性を継続的に問う

## アンチパターン

- **マイクロベンチマークの罠**: 隔離環境で速くても、実コードで効かない
- **早すぎるキャッシュ**: 整合性バグを呼ぶ
- **並列度上げすぎ**: 下流 (DB, API) を落とす
- **読みやすさを犠牲にした最適化**: 効果がプロファイラで実証されない限り却下
